struct hostent y la función gethostbyname()

La clase retomó lo visto en la sesión anterior: los sockets como puntos finales de comunicación entre procesos, la estructura struct sockaddr_in con el tipo in_addr y los dos datos que necesita un cliente para conectarse a un servidor: la dirección IP (o dominio) y el puerto lógico.

El problema del día: cómo obtener, desde C, la IP (o la lista de IPs) de un nombre de dominio legible como www.google.com. La biblioteca de C ofrece gethostbyname(const char *name), que consulta la base de hosts o el servidor DNS del sistema y devuelve un apuntador a una estructura struct hostent (o NULL si el dominio no existe o la consulta falla). Campos principales de struct hostent:

CampoTipoContenido
h_namechar *Nombre oficial o principal del host.
h_aliaseschar **Arreglo terminado en NULL con los nombres alternativos (alias) del dominio.
h_addrtypeenteroTipo de dirección devuelta (por ejemplo AF_INET para IPv4).
h_lengthenteroLongitud en bytes de la dirección (4 en IPv4).
h_addr_listchar **Arreglo de apuntadores con la lista de direcciones IP asociadas al dominio.

Detalle técnico clave sobre h_addr_list. En la definición de la estructura está declarado genéricamente como arreglo de cadenas (char **), pero en C las direcciones IP de Internet se representan con el tipo struct in_addr. Para recorrer el arreglo correctamente y sin corromper memoria hay que declarar una variable struct in_addr **addr_list y hacer un cast explícito:

struct in_addr **addr_list;
addr_list = (struct in_addr **) he->h_addr_list;

Distintos dominios devuelven un número variable de IPs (un sitio sencillo puede devolver una, una infraestructura masiva como Google muchas), así que el arreglo no tiene longitud fija. Se recorre aprovechando que el último elemento es un puntero NULL:

for (int i = 0; addr_list[i] != NULL; i++) {
    /* Procesamiento de cada IP */
}

Para que la salida en consola se vea natural, dentro del bucle se imprime i + 1, de modo que aparezca “IP 1”, “IP 2”… y no “IP 0” ante el usuario.

Explicado en simple

Es como buscar el nombre de una persona en la guía telefónica para obtener su nombre oficial y todas las líneas telefónicas asociadas a ella.Dónde falla la analogía: En la guía telefónica los números son texto legible, pero en C la estructura h_addr_list guarda las direcciones como estructuras binarias (struct in_addr) que requieren conversión explícita.

Por qué importa / con qué se conecta

Permite a un programa resolver nombres de dominio (como www.google.com) en las estructuras de direcciones IP binarias que requiere el sistema operativo para conectar sockets.

Errores comunes: Olvidar realizar el cast explícito de h_addr_list a (struct in_addr **) o no validar si gethostbyname() devolvió NULL al no encontrar el dominio.

Conversión de IP entre binario y decimal punteado: inet_ntoa e inet_aton

El kernel de Linux y los sockets guardan las IP internamente como enteros en formato binario de red (network format), mientras que las personas leemos notación decimal punteada (como 142.251.x.x). C ofrece dos funciones para traducir en ambos sentidos, y el profesor desglosó su nemotecnia para evitar confusiones:

  • inet_: Internet.
  • n: Network (formato binario de red, como lo entiende la máquina).
  • a: ASCII / Address (texto decimal punteado, legible por humanos).
  • to: “hacia”, indica el sentido de la conversión.

inet_ntoa() (Network to ASCII) recibe una struct in_addr con la IP en binario de red y devuelve una cadena (char *) en decimal punteado. inet_aton() (ASCII to Network) hace lo inverso: toma la cadena que escribió el usuario y la convierte a la struct in_addr que entiende la máquina. En el código de clase, como addr_list[i] es un apuntador a struct in_addr, se desreferencia con un asterisco para pasárselo a inet_ntoa() e imprimirlo con %s:

printf("IP %d: %s\n", i + 1, inet_ntoa(*addr_list[i]));
Explicado en simple

Es como un traductor bilingüe que convierte un mensaje en código Morse a texto en español y viceversa para que lo entiendan tanto la máquina como la persona.Dónde falla la analogía: El código Morse sigue siendo una cadena de caracteres, mientras que el formato de red es un entero binario de 32 bits en orden de red dentro de una estructura C.

Por qué importa / con qué se conecta

Las funciones de red del kernel exigen la IP en binario (struct in_addr), mientras que los usuarios e interfaces leen la IP en formato ASCII decimal punteado (como 142.251.x.x).

Errores comunes: Confundir la letra n (network/binario) con la a (ASCII/texto decimal) o no desreferenciar con un asterisco (*addr_list[i]) al pasar la estructura a inet_ntoa().

Alta disponibilidad (HA) y clústers. Aprovechando que Google devuelve varias IPs, el profesor explicó el clúster de alta disponibilidad: un conjunto de dos o más computadoras o servidores que trabajan coordinados para comportarse como un solo sistema. Dos estrategias de reparto de carga:

EstrategiaCómo funcionaCuándo conviene
Por capacidad / jerarquía (del más fuerte al más débil)Todas las peticiones van al servidor principal (el de mayor poder de cómputo). Cuando está por llegar al 100 % de su capacidad, “pasa la estafeta” al segundo; si este también se satura, al tercero, y así sucesivamente.Cuando los equipos del clúster tienen capacidades distintas.
Round-robin (anillo / reparto equitativo)Las peticiones se reparten cíclicamente: la 1 al servidor 1, la 2 al 2, …, la 8 al 8, y la 9 vuelve al servidor 1.Cuando todos los servidores tienen hardware similar.
Explicado en simple

Es como una sucursal bancaria con múltiples ventanillas de atención donde, si una se llena o falla, las demás atienden a los clientes entrantes.Dónde falla la analogía: Las ventanillas físicas están en un mismo edificio, pero los clústers de servidores distribuyen peticiones entre centros de datos en diferentes partes del mundo usando balanceo round-robin.

Por qué importa / con qué se conecta

Errores comunes: Los alumnos notaron que obtenían las mismas 8 direcciones IP de Google pero en diferente orden; el profesor aclaró que se debe al balanceo de carga cíclico (round-robin) y que www.google.com no devuelve lo mismo que google.com.

Formas de extraer la IP y el Programa 3

Se presentó el Programa 3 del tema (programa3.c), que amplía la inspección de struct hostent y muestra cuatro maneras de obtener e imprimir una IP desde C:

  1. Método A — inet_ntoa(): conversión directa de la estructura binaria a texto.
  2. Método B — inet_ntop() (Network to Presentation): la versión moderna y más segura, compatible con IPv4 e IPv6.
  3. Método C — acceso por octetos: se accede al campo h_addr con un cast explícito a (unsigned char *) para obtener un apuntador a los 4 bytes de la IP e imprimir cada octeto separado por puntos.
  4. Método D — valor crudo de 32 bits: se trata el valor como un único entero sin signo.

El programa también recorre el campo h_aliases para mostrar todos los nombres alternativos del host en el DNS.

Explicado en simple

Es como leer la dirección de una casa de cuatro formas distintas: la etiqueta postal completa, el código postal, los componentes individuales (calle, número e interior) o las coordenadas geográficas puras.Dónde falla la analogía: Las coordenadas o etiquetas siguen siendo texto escrito, mientras que los valores de 32 bits en memoria son enteros binarios crudos en orden de red.

Por qué importa / con qué se conecta

Muestra las distintas alternativas en C para manipular y descomponer una IP (inet_ntoa, inet_ntop, acceso directo a los 4 bytes de h_addr o valor entero crudo de 32 bits) e iterar sobre alias DNS.

Puertos lógicos y clasificación de la IANA

Un cliente necesita dos datos del servidor: IP (o dominio) y puerto lógico. El puerto lógico es una estructura de software representada por un número de 16 bits sin signo, lo que da 216 = 65,536 puertos, del 0 al 65535. La IANA (Internet Assigned Numbers Authority, iana.org) es la autoridad internacional que regula y asigna la correspondencia de números de puerto. Los puertos se dividen en tres rangos:

RangoNombreReglas
0 – 1023Puertos del sistema (reservados)Reservados para servicios esenciales del sistema operativo; solo el administrador (root / sudo) puede levantar un servicio ahí. El puerto 0 está reservado.
1024 – 49151Puertos de usuario (registrados)Para aplicaciones y servicios comunes; cualquier usuario puede usarlos si el puerto no está ocupado por otro proceso.
49152 – 65535Puertos dinámicos o privadosConexiones temporales, efímeras o de clientes privados.

Puertos emblemáticos revisados en la lista de la IANA:

  • 21 — FTP (transferencia de archivos).
  • 22 — SSH (conexión remota cifrada).
  • 23 — Telnet (conexión remota antigua y no segura, todo en texto plano).
  • 25 — SMTP (correo electrónico).
  • 80 — HTTP (creado por Tim Berners-Lee; las peticiones viajan en texto plano).
  • 443 — HTTPS (versión cifrada y segura de HTTP).
  • 666 — el videojuego Doom, que tiene ese puerto asignado para sus servidores multijugador en el registro oficial (y, curiosamente, aparece en la página 13 del documento).
Explicado en simple

Es como los números de departamento en un edificio de oficinas, donde cada número indica exactamente a qué empresa o servicio debes dirigirte.Dónde falla la analogía: Las oficinas físicas tienen muros y puertas reales, mientras que los puertos lógicos son estructuras numéricas de software de 16 bits gestionadas por el kernel.

Por qué importa / con qué se conecta

Es indispensable para direccionar el tráfico de red en la Capa 4, permitiendo que un mismo host distinga qué proceso debe atender la petición entre sus 65,536 puertos lógicos.

Errores comunes: Creer que un usuario sin privilegios de administrador (root) puede levantar un servicio en puertos menores a 1024.

Ciclo de vida de un socket: funciones de servidor y cliente

Al final el profesor proyectó el diagrama que guiará el resto del semestre: la secuencia de funciones en C que ejecutan el servidor y el cliente para comunicarse.

      SERVIDOR                                CLIENTE
   +------------+                          +------------+
   |  socket()  |                          |  socket()  |
   +-----+------+                          +-----+------+
         |                                       |
  [Inicializa struct                       [Inicializa struct
   sockaddr_in]                             sockaddr_in]
         |                                       |
   +-----+------+                                |
   |   bind()   |                                |
   +-----+------+                                |
         |                                       |
   +-----+------+                                |
   |  listen()  |                                |
   +-----+------+                                |
         |                                       |
   +-----+------+      Solicitud de        +-----+------+
   |  accept()  |<-------------------------|  connect() |
   +-----+------+      conexión            +-----+------+
         |                                       |
   +----------------------------------------------------+
   |  INTERCAMBIO DE DATOS (síncrono o asíncrono)       |
   |  send() / recv()     o     write() / read()        |
   +----------------------------------------------------+
         |                                       |
   +-----+------+                          +-----+------+
   |   close()  |                          |   close()  |
   +------------+                          +------------+

Secuencia del servidor:

  1. socket(): crea el socket y devuelve un descriptor de archivo entero.
  2. Inicialización de struct sockaddr_in con la familia (AF_INET), la IP (sin_addr) y el puerto (sin_port).
  3. bind(): “liga” la dirección IP y el puerto al socket creado.
  4. listen(): pone al servidor en escucha activa e inicializa la cola de peticiones entrantes (backlog).
  5. accept(): acepta la primera solicitud en cola; bloquea la ejecución hasta que llega un cliente y devuelve un nuevo descriptor de socket dedicado a esa sesión.

Secuencia del cliente: socket(), llenar su propia struct sockaddr_in con la IP y el puerto del servidor destino y connect(), que envía la solicitud de conexión y opera al mismo nivel que el accept() del servidor.

Intercambio de datos y buena práctica. Una vez conectados, la comunicación es envío y recepción de bytes, con dos pares de funciones: send()/recv() y write()/read() (en Linux un socket se maneja como descriptor de archivo). Regla estricta: usarlas siempre en parejas. Si un extremo usa send(), el otro debe usar recv(); si uno usa write(), el otro read(). Nunca mezclarlas (por ejemplo, send() con read() o write() con recv()).

  • Comunicación síncrona (lineal): orden alternado estricto; si un extremo hizo send(), no puede enviar otro mensaje hasta recibir la respuesta con recv().
  • Comunicación asíncrona: permite enviar n mensajes seguidos sin esperar una recepción intermedia.
  • Cierre: ambos procesos llaman a close(). El cliente termina su ejecución, mientras que el servidor cierra el socket de ese cliente pero regresa a accept() para seguir escuchando y atender al siguiente en la cola.
Explicado en simple

Es como la centralita de un restaurante donde un operador recibe la llamada entrante, la transfiere a una extensión privada con un mesero y regresa a esperar la siguiente llamada.Dónde falla la analogía: Las extensiones telefónicas usan conmutadores físicos, mientras que los sockets usan descriptores de archivo de software en la tabla de procesos de Linux.

Por qué importa / con qué se conecta

Define el flujo obligatorio de funciones en C para cliente y servidor, estableciendo que el servidor maneja dos sockets (conexión fd_s y comunicación fd_c) y la regla de no mezclar send/recv con write/read.

Errores comunes: Mezclar send() con read() o write() con recv(), o no comprender por qué el servidor ejecuta dos close() y regresa en recursividad a la función accept().

🧠 Ponte a prueba

Intenta contestar cada pregunta antes de abrirla. Recordar por tu cuenta es lo que fija la información; releer no la fija.

1. ¿Qué valor devuelve la función gethostbyname() si el nombre de dominio consultado no existe en el DNS y cómo debe validarse en C?

Devuelve un puntero nulo (NULL); en el código debe validarse inmediatamente con un condicional if (he == NULL) para imprimir un mensaje de error y terminar el programa.

2. Explica con tus palabras la diferencia funcional entre inet_ntoa() e inet_aton().

inet_ntoa() convierte una dirección IP desde su formato binario de red (struct in_addr) a una cadena de texto en decimal punteado, mientras que inet_aton() realiza la conversión inversa de texto decimal punteado a binario de red.

3. Si se desea desarrollar un servidor web en el puerto 80 dentro de Linux, ¿qué condición de privilegios se requiere para ejecutar la función bind()?

Se requieren privilegios de usuario administrador (root o sudo), ya que el puerto 80 pertenece al rango de puertos del sistema (0 a 1023) regulado por la IANA.

4. Compara la estrategia de balanceo de carga en clústers de alta disponibilidad basada en jerarquía frente a la estrategia Round-Robin.

La estrategia por jerarquía envía todo el tráfico al servidor más potente hasta saturarlo antes de pasar al segundo, mientras que Round-Robin distribuye las peticiones equitativamente en forma de anillo entre servidores con capacidades similares.

5. ¿Por qué en la función inet_ntoa(*addr_list[i]) se coloca un asterisco antes del elemento del arreglo?

Porque addr_list[i] es un puntero a struct in_addr, y se debe desreferenciar con el asterisco para pasar la estructura completa por valor a la función.

6. ¿Cuál es la regla de buena práctica establecida por el profesor referente al uso de send(), recv(), write() y read()?

Deben usarse siempre en parejas asociadas: si un extremo usa send() el otro usa recv(), y si usa write() el otro usa read(); nunca deben mezclarse entre sí.

7. Un dominio devuelve un arreglo de IPs en h_addr_list. ¿Cómo sabe el bucle for en C cuándo ha llegado al final del arreglo si no hay una variable de longitud?

El bucle evalúa la condición addr_list[i] != NULL, aprovechando que el último elemento del arreglo de punteros está configurado con un valor NULL.

8. Compara el rol del socket servidor (fd_s) con el del socket cliente aceptado (fd_c) en el lado del servidor.

El socket servidor (fd_s) es el socket de conexión que escucha en la IP y puerto del servidor, mientras que fd_c es el socket de comunicación devuelto por accept() para intercambiar datos con el cliente específico.

Puntos clave

  • gethostbyname() hace la consulta DNS y devuelve un struct hostent * (o NULL si falla); h_addr_list se castea a struct in_addr ** y se recorre hasta el NULL final.
  • inet_ntoa() pasa de binario de red a texto decimal punteado; inet_aton() hace lo contrario.
  • La IANA divide los 65,536 puertos en sistema (0–1023, requieren root), usuario (1024–49151) y dinámicos (49152–65535).
  • Servidor: socket → bind → listen → accept; cliente: socket → connect. Usar siempre parejas send/recv o write/read.
  • Un clúster de alta disponibilidad reparte la carga por capacidad (del más fuerte al más débil) o en round-robin.
