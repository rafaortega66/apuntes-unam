Consulta y estructura del manual de señales (man 7 signal)

Para inspeccionar las señales disponibles en la arquitectura del sistema se ejecuta man 7 signal (capítulo 7 del manual). Dentro de la sección Signal numbering for standard signals, hay que identificar la columna X86 ARM para la correspondencia exacta entre macro en C y número entero:

  • SIGINT (2): generada por Ctrl+C; interrumpe la ejecución, se puede ignorar o manejar.
  • SIGABRT (6): el proceso se la manda a sí mismo para abortar su ejecución.
  • SIGKILL (9): matanza ineludible e inmediata del proceso.
  • SIGTERM (15): solicitud de terminación enviada por utilidades del sistema (ej. shutdown); puede ignorarse o tratarse.
  • SIGCHLD/SIGCLD (17 en X86/ARM, 18 en otras): enviada por el hijo a su padre al terminar su tarea.
La función signal() y sus 3 escenarios

Prototipo, en <signal.h>:

void (*signal(int sig, void (*func)(int)))(int);

Escenario 1 — Ignorar la señal (SIG_IGN):

signal(SIGINT, SIG_IGN);

Con un ciclo while(1), cualquier Ctrl+C es ignorado y el proceso sigue corriendo. Para volver al comportamiento nativo se sustituye por SIG_DFL, que destruye el proceso al presionar Ctrl+C.

Escenario 2 — Manejar/tratar la señal con una función personalizada: debe cumplir estrictamente el prototipo void nombre_funcion(int param).

void manejador_senales(int sig) {
    if (sig == SIGINT) {
        printf("Señal número %d recibida\n", sig);
    }
}

int main() {
    signal(SIGINT, manejador_senales);
    while(1) {
        printf("En espera de Ctrl+C. PID: %d\n", getpid());
        sleep(5);
    }
    return 0;
}
  • Versión 1 (el proceso sigue vivo): tras ejecutar el manejador, el flujo regresa al while(1) y el proceso continúa normalmente.
  • Versión 2 (el proceso termina tras el tratamiento): se invoca exit(0) dentro del manejador (o se condiciona a un número de interrupciones con una variable static int cnt), haciendo que el programa haga su limpieza y termine de forma limpia.

Escenario 3 — Señales inalterables / no capturables: el sistema no permite redirigir ni bloquear ciertas señales. Ejemplo principal: SIGKILL (9).

Analogía del profesor: SIGKILL equivale al hechizo Avada Kedavra de Harry Potter: fulminante, ineludible, ningún código puede proteger al proceso de ella. Si se intenta signal(SIGKILL, manejador_senales), la llamada regresa un valor de error indicando que no se puede capturar esa señal.

Procesos en primer plano (foreground) y segundo plano (background)
  • Foreground: el proceso está atado a la terminal activa, recibe la entrada estándar del teclado y bloquea la consola mientras se ejecuta.
  • Background: el proceso corre en tiempo compartido en segundo plano, dejando la línea de comandos libre para lanzar otros programas en paralelo.

Secuencia para enviar un proceso a background:

  1. Ejecutar el proceso en primer plano.
  2. Presionar Ctrl+Z para enviar SIGTSTP, dejando el proceso pausado (Stopped).
  3. Escribir bg en el prompt — el sistema lo reanuda en segundo plano e imprime su identificador de trabajo entre corchetes (ej. [33]).

Inconveniente: si el proceso en background tiene printf(), el texto se sigue imprimiendo en la terminal, desplazando el prompt mientras el usuario escribe otros comandos. Para evitarlo, redirigir la salida a un archivo o a /dev/null.

Administración de trabajos: jobs lista los trabajos activos en background ([33], [36], etc.); fg %N trae de vuelta el trabajo N a primer plano — necesario si se le quiere mandar una interrupción Ctrl+C, ya que esa combinación solo afecta al proceso activo en foreground.

Huérfano vs. zombie (distinción marcada para examen): un huérfano es un proceso cuyo padre muere primero y que el sistema adopta (PID 1 o un reaper); un zombie es lo contrario — el hijo ya murió, pero el padre no ha procesado la señal SIGCHLD ni limpiado su entrada en la tabla de procesos, así que sigue apareciendo en el sistema. El profesor remarcó que la captura correcta de señales y el control de procesos concurrentes será un requisito práctico indispensable del proyecto final de la materia.

Puntos clave

  • Ante una señal hay tres escenarios: ignorarla (SIG_IGN), tratarla con un manejador void función(int), o dejar que termine el proceso si no puede ignorarse ni tratarse.
  • SIGKILL (9) es inalterable — ni se ignora, ni se bloquea, ni se maneja, bajo ninguna circunstancia.
  • SIGCHLD es la señal 17 en X86/ARM (18 en la numeración genérica de UNIX System V) que el hijo manda al padre al morir.
  • Huérfano (padre muere primero, lo adopta PID 1/reaper) es lo opuesto a zombie (hijo ya murió, padre no ha limpiado su entrada con wait()/SIGCHLD).
  • Ctrl+Z detiene sin destruir, bg reanuda en segundo plano, jobs lista trabajos y fg %N trae uno de vuelta a primer plano.
