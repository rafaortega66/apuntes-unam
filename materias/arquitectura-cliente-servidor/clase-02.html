Clase 2 — permisos, bit setuid, /etc/passwd y fork()
Explicado en simple

Es como una credencial de visitante en un edificio de oficinas: normalmente tu pase solo te permite andar por el vestíbulo, pero si te asignan un permiso especial grabado en la tarjeta, puedes actuar temporalmente como administrador mientras realizas una tarea específica.Dónde falla la analogía: Deja de servir en cuanto termina la ejecución del programa o sales de la aplicación, momento en el cual pierdes los privilegios especiales y vuelves automáticamente a tu identidad común.

Por qué importa / con qué se conecta

Conecta la administración de seguridad de Linux con la programación de procesos en C, demostrando cómo los programas pueden elevar privilegios de forma temporal para acceder a archivos protegidos del sistema.

Errores comunes: Confundir las siglas del modelo de permisos UGO pensando que la letra «O» corresponde a «owner» (dueño) en lugar de «others» (otros usuarios del sistema).

Permisos UGO y chmod (notación decimal)

Regla mnemotécnica: "ugo" (como "Hugo" sin H) → Usuario (dueño), Grupo, Otros. chmod = change mode.

  r  w  x
  4  2  1        rwx = 4+2+1 = 7      rw- = 6      r-x = 5
  • chmod 777 archivo — todos los permisos para u, g y o.
  • chmod 644 archivo — archivo editable no ejecutable: dueño rw (6), grupo y otros r (4).
  • chmod 755 archivo — ejecutable típico: dueño rwx (7), grupo y otros r-x (5).
Explicado en simple

Es como un tablero con tres conjuntos de interruptores para el dueño, el grupo y el resto de las personas, donde la luz de lectura vale 4 puntos, la de escritura 2 puntos y la de ejecución 1 punto, sumando sus valores para encender los permisos deseados.Dónde falla la analogía: Deja de servir si intentas otorgar permiso de ejecución a un archivo de texto o documento que no contiene código ejecutable, ya que el sistema operativo no podrá correrlo como programa.

Por qué importa / con qué se conecta

Permite establecer el control de acceso a archivos y ejecutables mediante comandos octales en la terminal como chmod 755 o chmod 644 antes de desplegar servicios de red.

Errores comunes: Olvidar que para poder ejecutar un archivo ejecutable binario en Linux es indispensable contar también con el permiso de lectura activado.

Bit SetUID (chmod con 4 dígitos)

Al ejecutar un binario, el proceso normalmente pertenece a quien lo ejecuta. Con el bit SetUID activo, quien lo ejecuta toma temporalmente los privilegios del dueño del archivo mientras dura la ejecución.

Se activa con un cuarto dígito a la izquierda en chmod, que indica sobre qué bloque:

4 = SetUID   (bloque de usuario)   ← el más usado
2 = SetGID   (bloque de grupo)
1 = sticky   (bloque de otros)
ej.  chmod 4511 archivo

⚠️ Riesgo de seguridad: si root pone SetUID a un ejecutable, cualquier usuario sin privilegios se vuelve root durante esa ejecución. Manejar con extrema precaución.

Explicado en simple

Es como agregar una cuarta palanca maestra al tablero que le dice a la puerta: sin importar quién introduzca la llave para girarla, dale acceso con todos los derechos del dueño de la casa durante esa visita.Dónde falla la analogía: Deja de servir si el programa ejecutado contiene fallas de seguridad o código malicioso, ya que permitiría a cualquier usuario común tomar control total del sistema como root.

Por qué importa / con qué se conecta

Se representa con una letra «s» en el lugar del permiso de ejecución del usuario (r-s) al utilizar un comando de 4 dígitos como chmod 4511.

Errores comunes: Pensar que el bit SetUID modifica de forma permanente la cuenta de usuario en el sistema operativo, cuando únicamente afecta la duración del proceso en ejecución.

Usuarios en Linux · /etc/passwd · ID real vs. efectivo
  • ID real → dueño legítimo del proceso / archivo; es el que asigna /etc/passwd. Se obtiene con getuid() (igual que getpid() / getppid()).
  • ID efectivo → el usuario que está corriendo el programa en ese instante. Se obtiene con geteuid() (la "e" = effective).

cat /etc/passwd — campos separados por :

username : x : UID : GID : nombre_real : /home/... : shell
   |       |    |     |        |            |          |
 el 1º   contraseña  id    id de     GECOS (si no    dir.   tipo de
 es root  oculta   usuario  grupo    se puso, =user) home   shell

Usuarios de sistema con shell nologin: no pueden iniciar sesión interactiva (seguridad). [inaudible: la ruta se oye como "etc/al passworden"]

Explicado en simple

El ID real es tu número de pasaporte oficial registrado en el registro civil, mientras que el ID efectivo es la identificación temporal o disfraz de trabajo que te pones para entrar a una zona restringida.Dónde falla la analogía: Deja de servir en cuanto la ejecución del programa finaliza, porque el disfraz no altera tu número de registro civil permanente en el sistema.

Por qué importa / con qué se conecta

Muestra cómo funciones en C como getuid() y geteuid() consultan los datos de usuario registrados en /etc/passwd para validar el control de acceso y la elevación de privilegios.

Tarea 2 — probar el bit SetUID

Metodología: dos terminales (una como root, otra como usuario sin privilegios). Las instrucciones de pantalla dividida en Codespaces están en la carpeta del Tema 3 del repo, aunque se usan desde el Tema 1. whoami muestra el usuario activo.

fdisk = comando solo-root para manipular la tabla de particiones (man fdisk). Sirve cualquier comando que pida privilegios. Pasos:

# 1) como usuario NO root:
fdisk -l                     # -> "permiso denegado"
                             #    (en Fedora puede solo regresar el prompt vacío)

# 2) como root, ver permisos actuales:
ls -l /sbin/fdisk            # -> 755  (rwxr-xr-x)

# 3) como root, activar SetUID:
chmod 4511 /sbin/fdisk       # -> r-s--x--x  (la 's' en vez de 'x' = SetUID activo;
                             #    el nombre se ve en rojo si hay color)

# 4) como usuario NO root otra vez:
fdisk -l                     # -> AHORA SÍ funciona: lista las particiones

# 5) OBLIGATORIO: revertir de inmediato
chmod 755 /sbin/fdisk        # (o los permisos que tuviera antes)

[inaudible: la ruta se dicta rápido como "diagonal se bin diagonal fis" → /sbin/fdisk]

fork() — creación de procesos
  • Mecanismo nativo del kernel de Linux para crear procesos.
  • Es costoso: clona / duplica toda la estructura de memoria del proceso que lo llama.
  • El proceso hijo es copia idéntica del padre en datos y variables, salvo su PID y su PPID.
  • Tras fork(), padre e hijo corren en paralelo y asíncronos (ráfagas de CPU alternadas).

Retorno (tipo pid_t, encapsula un entero; se imprime con %d / %i):

al PADRE  ->  el PID del hijo   (entero != 0)
al HIJO   ->  0

La variable donde guardas el retorno se duplica: en el padre vale el PID del hijo, en el hijo vale 0. Se separa el código con:

if (id_hijo != 0) {
    // código exclusivo del padre
} else {
    // código exclusivo del hijo
}

Sin if, todo lo que va después de fork() se ejecuta en ambos → sale duplicado. En programa05_fork_v1.c: la línea de antes del fork() se imprime una vez; las dos de después, dos veces cada una.

Nota semántica del profesor: antes del fork() lo llama "proceso main / principal"; "padre" solo cuando ya hay hijo.

Explicado en simple

Es como una máquina de clonación instantánea que duplica a una persona junto con todo lo que lleva en las manos en ese instante, dejando que ambas sigan caminando hacia adelante de forma independiente.Dónde falla la analogía: Deja de servir si se piensa que las dos personas clonadas comparten la misma mente o memoria física en tiempo real, ya que en el kernel los procesos operan en espacios separados.

Por qué importa / con qué se conecta

Es la llamada al sistema fundamental en sistemas Unix/Linux para la creación de procesos, devolviendo al padre el PID del hijo y al hijo un valor de 0.

Errores comunes: Asumir que el proceso padre y el proceso hijo se ejecutan en un orden secuencial estricto y predecible, olvidando que corren de forma asíncrona bajo una condición de carrera.

examen⚠️ Deadlock (candado / abrazo mortal)

Si el padre espera a que termine el hijo para continuar y a la vez el hijo espera a que termine el padre → bloqueo indefinido. Única salida: Ctrl + C.

Ejemplo de ejecución — programa05_fork_v2.c

Explicado en simple

Es como llegar a un cruce de caminos con una instrucción clara: si tu número asignado es mayor a cero toma el camino de la derecha; si tu número asignado es cero toma el de la izquierda.Dónde falla la analogía: Deja de servir si se omite la evaluación condicional con if/else, haciendo que ambos caminantes recorran ambos senderos e impriman los mismos mensajes por duplicado.

Por qué importa / con qué se conecta

Muestra cómo evaluar la variable que guarda el retorno de fork() mediante if (id_hijo != 0) para separar la lógica de código del padre respecto a la del hijo usando getpid() y getppid().

Errores comunes: Tratar de adivinar cuál de los dos procesos terminará primero su salida en la terminal, ya que el planificador de tiempo compartido del sistema asigna turnos dinámicamente.

🧠 Ponte a prueba

Intenta contestar cada pregunta antes de abrirla. Recordar por tu cuenta es lo que fija la información; releer no la fija.

1. ¿Qué valor de retorno entrega la función fork() al proceso padre y cuál al proceso hijo en Linux?

Al proceso padre le devuelve el identificador de proceso (PID) del hijo recién creado, mientras que al proceso hijo le devuelve exactamente el valor 0.

2. Explica con tus palabras qué diferencia existe entre el ID real de usuario y el ID efectivo de usuario.

El ID real identifica al usuario dueño legítimo de la cuenta registrado en /etc/passwd, mientras que el ID efectivo es el identificador de privilegios que el proceso asume temporalmente durante su ejecución.

3. Si un archivo ejecutable tiene permisos iniciales 755 y aplicas el comando chmod 4755 sobre él, ¿qué permisos resultantes tendrá y en qué terna se activa la «s»?

Tendrá permisos rwsr-xr-x (notación octal 4755), activando el bit SetUID representado con una letra «s» en la terna correspondiente al usuario dueño del archivo.

4. Compara los permisos en notación decimal 644 y 755 indicando para qué tipo de archivo se recomienda cada uno.

El permiso 644 otorga lectura y escritura al dueño y solo lectura a grupo y otros, ideal para archivos de texto editables; el 755 otorga además permiso de ejecución a las tres ternas, ideal para ejecutables.

5. ¿Cuáles son los dos únicos atributos en los que un proceso hijo difiere de su proceso padre tras llamar a la función fork()?

Difiere únicamente en su propio identificador de proceso (PID) y en el identificador de su proceso padre (PPID).

6. Explica qué sucede si dentro de un programa en C que llama a fork() no se incluye una estructura condicional if/else para evaluar el valor devuelto.

Tanto el proceso padre como el proceso hijo continuarán ejecutando de forma independiente y duplicada todo el código fuente situado después de la llamada a fork().

7. Si el proceso padre tiene un PID de 30405 y llama a fork(), ¿qué valores devolverán getpid() y getppid() dentro del bloque de ejecución del hijo?

La función getpid() dentro del hijo devolverá su propio identificador (por ejemplo, 30406) y la función getppid() devolverá 30405, que corresponde al PID de su padre.

8. Compara la salida en pantalla al ejecutar el programa de prueba del bit SetUID antes y después de aplicar chmod 4511 con un usuario no-root.

Antes de aplicar chmod 4511 el programa muestra el mismo valor numérico para el usuario real y el efectivo (ej. 1000 y 1000); después de aplicarlo muestra usuario real 1000 y usuario efectivo 0 (root).
