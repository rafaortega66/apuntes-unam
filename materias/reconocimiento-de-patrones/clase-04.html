Repaso de cierre — PCA vs. LDA y otros métodos de reducción

La sesión arrancó resolviendo dudas de logística de la Práctica 1 (el profesor dio libertad de exponer apoyándose en el código o en el reporte escrito, según lo que cada equipo prefiriera). Después, repasó la diferencia fundamental entre PCA y LDA con una pregunta directa: "¿Se acuerdan cuál era la diferencia más importante entre lo que implica PCA y LDA?" El alumno Sebastián respondió que LDA es un método supervisado. El profesor confirmó y precisó: LDA es supervisado porque requiere una etiqueta (label) que indica explícitamente a qué clase pertenece cada patrón; PCA, en cambio, es no supervisado — no necesita conocer de antemano la clase de los patrones.

  • En cuanto a objetivos matemáticos: PCA maximiza la varianza total proyectada; LDA maximiza la separabilidad entre clases.
  • Tres supuestos de LDA: 1) distribución gaussiana por clase; 2) homocedasticidad (matriz de covarianza idéntica entre clases); 3) separabilidad lineal. Cuando estos supuestos no se cumplen del todo en datos reales, se introduce cierto error, pero LDA sigue siendo útil como aproximación.
  • QDA = LDA sin el supuesto de covarianza única: cada clase tiene su propia matriz de covarianza.
  • t-SNE (visualización en 2D/3D) y Kernel PCA (kernel trick → proyectar a mayor dimensión donde sea linealmente separable, luego PCA).
Explicado en simple

Es como resumir un álbum de fotos familiares: un método organiza las fotos buscando la luz y el ángulo con mayor variación sin mirar las etiquetas, mientras que otro busca resaltar al máximo las diferencias entre familiares para identificarlos rápido.Dónde falla la analogía: Deja de funcionar si los datos de las distintas categorías no siguen una distribución normal o si cada categoría tiene una dispersión completamente diferente a las demás.

Por qué importa / con qué se conecta

Conecta la reducción de dimensionalidad no supervisada (PCA, enfocado en maximizar varianza) con la supervisada (LDA, enfocado en maximizar la separabilidad entre clases usando etiquetas), estableciendo el punto de partida antes de pasar a la evaluación de clasificadores.

Errores comunes: Dudar sobre la diferencia fundamental entre métodos supervisados y no supervisados, donde se aclaró que lo supervisado requiere necesariamente etiquetas previas de clase para cada patrón.

Matriz de confusión y tipos de error

Matriz de confusión: tabla de contingencia que resume las predicciones de un clasificador. Filas = clases reales (ground truth); columnas = clases predichas. Diagonal principal = aciertos; triángulos = errores.

  • VP (verdadero positivo): era positivo y se predijo positivo.
  • FN (falso negativo): era positivo y se predijo negativo — Error Tipo II (p. ej. no activar la alarma habiendo incendio; suele ser el más peligroso).
  • FP (falso positivo): era negativo y se predijo positivo — Error Tipo I (p. ej. activar la alarma sin fuego).
  • VN (verdadero negativo): era negativo y se predijo negativo.
Explicado en simple

Es como un sistema de alarma contra incendios que puede sonar cuando hay fuego (verdadero positivo), estar en silencio sin fuego (verdadero negativo), sonar cuando no hay fuego (falso positivo o falsa alarma, Error Tipo I) o no sonar habiendo fuego (falso negativo, Error Tipo II catastrófico).Dónde falla la analogía: Se rompe cuando el sistema no clasifica eventos en categorías discretas sino que predice valores numéricos continuos, donde las fallas no se pueden resumir en aciertos y falsas alarmas.

Por qué importa / con qué se conecta

Es la herramienta fundamental que resume las predicciones de un clasificador mediante una matriz de doble entrada comparando lo que el modelo predijo contra la realidad.

Métricas de evaluación 
Exactitud (Accuracy)     = (VP + VN) / (VP + FN + FP + VN)
Precisión                = VP / (VP + FP)          (de lo predicho positivo, cuánto lo era)
Recall / Sensibilidad    = VP / (VP + FN)          (de lo positivo real, cuánto se capturó)
Especificidad            = VN / (VN + FP)          (de lo negativo real, cuánto se identificó)
F1-Score                 = 2 · (Precisión · Recall) / (Precisión + Recall)     (media armónica)
Exactitud balanceada     = (Sensibilidad + Especificidad) / 2

El F₁ penaliza fuerte los desequilibrios extremos entre precisión y recall. La exactitud balanceada es útil en conjuntos desbalanceados.

Ejemplo — Spam vs. No Spam (modelo equilibrado): Accuracy 90 % · Precisión 85.7 % · Recall 85.7 % · F₁ 85.7 %.

Explicado en simple

La exactitud mide el porcentaje total de aciertos; la precisión mide qué tan seguro es el modelo cuando dice que algo es positivo; el recall mide cuántos de todos los casos reales logró atrapar; y el F1-score es el promedio equilibrado entre ambos.Dónde falla la analogía: La exactitud (Accuracy) deja de servir por completo en problemas desbalanceados, como decir siempre que nadie tiene cáncer y obtener 95% de exactitud sin haber detectado a un solo enfermo.

Por qué importa / con qué se conecta

Permite evaluar cuantitativamente la calidad de las predicciones según el costo de los errores del problema mediante fórmulas exactas: Accuracy = (TP + TN) / (TP + TN + FP + FN), Precision = TP / (TP + FP), Recall = TP / (TP + FN), Specificity = TN / (TN + FP), F1-Score = 2 (Precision Recall) / (Precision + Recall) y Balanced Accuracy = (Sensitivity + Specificity) / 2.

Errores comunes: Confundir la precisión con el recall al momento de explicarlos, aclarado por el profesor especificando que la precisión se calcula sobre lo predicho como positivo y el recall sobre el total real de positivos.

Curva ROC y AUC

La curva ROC (Receiver Operating Characteristic) evalúa un clasificador probabilístico a lo largo de distintos umbrales de decisión.

Eje X  = FPR (tasa de falsos positivos) = FP / (FP + VN) = 1 − Especificidad
Eje Y  = TPR (tasa de verdaderos positivos) = VP / (VP + FN) = Recall = Sensibilidad

AUC (área bajo la curva ROC), escala de interpretación:

  • AUC = 1.0 — clasificador perfecto.
  • 0.9 ≤ AUC < 1.0 — excelente · 0.7 ≤ AUC < 0.9 — bueno · 0.5 ≤ AUC < 0.7 — regular.
  • AUC = 0.5 — equivale al azar (la diagonal).
  • AUC < 0.5 — peor que el azar: la predicción está invertida (el modelo distingue muy bien la clase contraria → invertir la predicción).

El profesor lanzó una pregunta sobre este último caso: "Si la curva ROC de un clasificador, en lugar de pegarse a la esquina superior izquierda, se desplaza hacia abajo de la diagonal, ¿qué significa?" Un alumno respondió: "Se equivocan todos" / "Detecta mejor la clase contraria". El profesor confirmó que la respuesta es correcta en el sentido práctico: si la curva está por debajo de la diagonal, el modelo es pésimo detectando la clase positiva pero sumamente efectivo detectando la clase negativa — en ese escenario el clasificador sigue siendo útil, basta con invertir la regla de predicción para transformarlo inmediatamente en un clasificador excelente. La única zona donde el modelo es completamente inservible es cuando se aproxima a la diagonal misma (AUC ≈ 0.5).

Explicado en simple

Es como ajustar la sensibilidad del detector de metales de un aeropuerto desde muy estricto hasta muy relajado, graficando en cada nivel cuántos objetos prohibidos detectas frente a cuántas falsas alarmas generas.Dónde falla la analogía: No se puede utilizar cuando el clasificador entrega directamente una etiqueta categórica rígida en lugar de un valor de probabilidad continuo entre 0 y 1.

Por qué importa / con qué se conecta

Evalúa el rendimiento de un modelo probabilístico a través de todos los umbrales de decisión posibles trazando la tasa de verdaderos positivos (TPR = Recall) frente a la de falsos positivos (FPR = 1 - Especificidad), obteniendo el área bajo la curva (AUC) donde 1.0 es perfecto, 0.5 es aleatorio y menos de 0.5 exige invertir la predicción.

Errores comunes: Creer que un modelo con un área bajo la curva menor a 0.5 no sirve para nada, cuando en realidad es muy bueno prediciendo la clase opuesta y basta con invertir sus predicciones.

Sesgo, varianza, underfitting y overfitting
  • Sesgo (bias): error sistemático por suposiciones incorrectas o simplificación excesiva. Analogía: arquero que siempre dispara desfasado a la izquierda (consistentemente inexacto).
  • Varianza (variance): sensibilidad excesiva al ruido del conjunto de entrenamiento. Analogía: arquero que dispara en todas direcciones.
  • Underfitting (alto sesgo): el modelo es demasiado simple → error alto en train y en val.
  • Overfitting (alta varianza): el modelo memoriza el ruido → error muy bajo en train, alto en val.

Partición de datos: Entrenamiento (60–80 %, ajusta los parámetros) · Validación (10–20 %, ajusta hiperparámetros y mide generalización) · Prueba (10–20 %, intocado hasta la evaluación final).

Degradación normal (no patológica): Accuracy Train 95 % → Val 91 % → Test 87 %.

Analogía de estudio: underfitting = un alumno decide memorizar únicamente una fórmula (por ejemplo, cómo calcular el determinante) para resolver absolutamente todo el examen — reprueba porque esa simplificación tan severa no sirve para la diversidad de preguntas reales. Overfitting = un alumno consigue los exámenes de los últimos 5 años y se memoriza las respuestas exactas con puntos y comas — reprueba igual porque el profesor cambia los números y variables en el examen real.

Un alumno preguntó si, cuando un modelo cae en overfitting o underfitting, se puede arreglar o es mejor rehacerlo desde cero. El profesor respondió que sí se puede arreglar ajustando el proceso de entrenamiento: en underfitting, la causa habitual es haber detenido el entrenamiento antes de tiempo o usar un modelo demasiado simple; en overfitting, la solución es aplicar regularización, aumentación de datos, o early stopping (parada temprana) — una técnica que monitorea la métrica de validación y detiene el entrenamiento automáticamente en el momento óptimo, antes de que el modelo empiece a memorizar ruido.

Explicado en simple

El sesgo (Underfitting) es como un estudiante que solo se aprende una fórmula simple y reprueba porque no abarca la materia; la varianza (Overfitting) es como un estudiante que se aprende de memoria los exámenes pasados con puntos y comas, y colapsa cuando en el examen real le cambian un número.Dónde falla la analogía: La analogía se rompe si el conjunto de datos de entrenamiento fuera infinito y libre de ruido, en cuyo caso memorizar el entrenamiento no causaría errores en la prueba.

Por qué importa / con qué se conecta

Permite diagnosticar si el modelo es demasiado simple (alto sesgo: error alto tanto en entrenamiento como en validación) o si memorizó el ruido (alta varianza: error muy bajo en entrenamiento y muy alto en validación), buscando siempre un balance óptimo.

Errores comunes: Confundir una ligera degradación natural del desempeño al pasar de entrenamiento a validación con un caso de sobreentrenamiento severo, lo cual fue aclarado por el profesor.

Datos desbalanceados

Ejemplo — detección de cáncer: 1 000 pacientes (950 sanos = 95 %, 50 enfermos = 5 %). Un modelo que predice "todos sanos" → Accuracy = 950/1000 = 95 %, pero detecta 0 de 50 casos de cáncer (50 falsos negativos). La exactitud alta esconde un modelo inútil.

El profesor dio ejemplos reales de qué tan severo puede ser el desbalance en la práctica: en detección de fraude financiero, solo cerca del 0.1% de las transacciones son realmente fraudulentas; en diagnóstico de cáncer, entre el 1% y el 5% de los pacientes analizados presentan la enfermedad; en detección de intrusos en redes, alrededor del 0.5% del tráfico web es verdaderamente malicioso.

Estrategias para evitar sesgos hacia la clase minoritaria: usar métricas adecuadas (F₁, balanced accuracy, ROC) · pesos de clase (class weights) · re-muestreo (resampling, incluyendo oversampling sintético de la clase minoritaria) · volver más exigente el umbral de decisión.

Explicado en simple

Es como buscar una aguja en un pajar donde el 99.9% es paja (transacciones normales) y solo el 0.1% es la aguja (fraude), por lo que decir siempre "paja" parece dar casi un 100% de aciertos pero no resuelve el problema.Dónde falla la analogía: Falla si se aplican ajustes de umbrales o re-muestreos sin conocer el contexto del dominio, ya que se puede generar un volumen intolerable de falsos positivos.

Por qué importa / con qué se conecta

Permite abordar problemas reales desbalanceados como detección de fraude (0.1%), cáncer (1-5%) e intrusiones de red (0.5%), mediante el uso de métricas adecuadas, ajuste de pesos de clase (class_weight), técnicas de re-muestreo (resampling) y modificación del umbral de decisión.

Errores comunes: Intentar evaluar un modelo con datos desbalanceados usando únicamente la exactitud (Accuracy), ignorando que el modelo jamás detecta la clase minoritaria de interés.

Esquemas de validación
  • Hold-out: división fija en Train / Val / Test. Desventaja: es altamente sensible a la partición — si por azar los datos "fáciles" quedan concentrados en un subconjunto, el resultado no representa el desempeño real.
  • K-Fold Cross Validation: se separa primero el conjunto de prueba final, y el resto se divide en K folds; el procedimiento itera K veces consecutivas, usando un fold distinto como validación cada vez. Por convención se usan números impares.
  • Stratified K-Fold: conserva la proporción original de las clases en cada fold. Necesario/obligatorio con datos desbalanceados.

Durante esta parte surgieron varias preguntas que vale la pena tener presentes:

  • "¿Sería posible entrenar con datos muy abstractos o difíciles y evaluar con datos más sencillos?" — el profesor respondió que sería técnicamente posible, pero equivaldría a "hacer trampa": el resultado no sería justo ni representativo, porque el modelo debe observar datos que reflejen la distribución real completa.
  • "¿La validación cruzada solo se aplica dentro del conjunto de entrenamiento?" — el profesor confirmó que sí, exactamente: el conjunto de prueba se separa desde el principio y no se toca; la validación cruzada se ejecuta solo dentro de entrenamiento/validación, para encontrar la mejor combinación de hiperparámetros. Una vez identificados los mejores hiperparámetros, se reentrena el modelo con todo el conjunto de entrenamiento/validación y se hace la única evaluación definitiva sobre el conjunto de prueba reservado.
  • "¿Cómo se determina el número de folds?" — por convención se eligen números impares. En datasets reducidos (por ejemplo, 200 imágenes) se recomiendan menos folds; en datasets masivos con miles o millones de muestras se pueden usar 9 o más. Usar valores excesivamente altos (15 o 20) en modelos simples no aporta beneficio real y solo añade costo computacional.
Explicado en simple

Hold-out es dividir tus datos una sola vez en entrenamiento, validación y prueba; K-Fold es dividirlos en K partes y realizar K evaluaciones rotando el bloque de prueba; y Stratified K-Fold asegura que cada parte tenga exactamente la misma proporción de cada clase.Dónde falla la analogía: K-Fold tradicional falla en datos desbalanceados porque al dividir al azar algunos bloques pueden quedar completamente vacíos de la clase minoritaria.

Por qué importa / con qué se conecta

Garantiza la capacidad de generalización del modelo evitando evaluarlo con los mismos datos con los que entrenó, lo cual sería como darle a un estudiante el mismo examen que resolvió en clase.

Errores comunes: Proponer entrenar el modelo únicamente con los datos más complejos y evaluarlo con los más sencillos, lo cual el profesor señaló como inadecuado por poder degradar o distorsionar el desempeño.

Fuga de datos y data drift

Fuga de datos (data leakage): contaminar el entrenamiento con información de validación o prueba.

  • Temporal: usar información del futuro para predecir el pasado.
  • De procesamiento: calcular normalización / PCA con estadísticas del conjunto global en vez de solo las de entrenamiento.
  • Del target: incluir como característica de entrada variables derivadas directamente de la variable objetivo.
  • En modelos de lenguaje: entrenar una red neuronal mostrándole directamente la palabra o la oración completa que se supone debe predecir.

Data drift: cambio en las propiedades estadísticas de los datos en producción respecto a la distribución de entrenamiento. El profesor advirtió que el data drift no provoca un fallo repentino en el sistema, sino una degradación silenciosa y progresiva del desempeño a lo largo del tiempo — por eso hay que monitorear constantemente los estadísticos del entorno de producción y compararlos contra los de entrenamiento.

Un alumno preguntó: al encontrar un drift, ¿es mejor reentrenar un modelo nuevo desde cero o se puede rescatar el anterior? El profesor respondió que se reentrena desde cero, pero utilizando una ventana móvil de datos recientes — no tiene sentido incluir datos históricos obsoletos si las condiciones actuales ya cambiaron.

Explicado en simple

La fuga de datos (Data Leakage) es como hacer trampa en un examen porque la hoja de preguntas incluye pistas de las respuestas; el Data Drift es cuando el examen cambia gradualmente con los años mientras tú sigues estudiando con la guía de hace una década.Dónde falla la analogía: El Data Drift no aplica si las condiciones estadísticas del entorno real son absolutamente estáticas e inmutables en el tiempo.

Por qué importa / con qué se conecta

Evita métricas engañosamente optimistas causadas por contaminación entre entrenamiento y prueba (fuga temporal, de preprocesamiento o del target) y monitorea la degradación silenciosa del modelo en producción para reentrenarlo desde cero.

Errores comunes: Calcular la normalización o el PCA utilizando las estadísticas de todo el dataset antes de separar el conjunto de prueba, provocando una fuga de datos de preprocesamiento.

Intenta contestar cada pregunta antes de abrirla. Recordar por tu cuenta es lo que fija la información; releer no la fija.

1. ¿Qué es la matriz de confusión y qué representan los errores Tipo I y Tipo II según la analogía de la alarma de incendio explicada en clase?

La matriz de confusión es una tabla que resume las predicciones de un clasificador frente a la realidad. En la analogía de la alarma de incendio, el Error Tipo I es un Falso Positivo (no hay fuego pero la alarma suena, es decir, una falsa alarma) y el Error Tipo II es un Falso Negativo (hay fuego pero la alarma no suena, lo cual es un error catastrófico).

2. En un dataset de 100 correos electrónicos, un modelo predice 35 como spam. De ellos, 30 eran realmente spam (TP = 30, FP = 5). Además, se le escaparon 5 correos de spam que clasificó como no spam (FN = 5) y clasificó correctamente 60 correos normales (TN = 60). Calcula la Exactitud (Accuracy), la Precisión y el Recall.

La Exactitud es (TP + TN) / Total = (30 + 60) / 100 = 0.90 o 90%. La Precisión es TP / (TP + FP) = 30 / (30 + 5) = 30 / 35 = 0.857 u 85.7%. El Recall es TP / (TP + FN) = 30 / (30 + 5) = 30 / 35 = 0.857 u 85.7%.

3. ¿Cómo se diferencian el sesgo (underfitting) y la varianza (overfitting) en términos de los errores observados en los conjuntos de entrenamiento y validación?

En el sesgo alto (underfitting) el modelo es demasiado simple y presenta un error alto tanto en entrenamiento como en validación. En la varianza alta (overfitting) el modelo memoriza el entrenamiento, presentando un error muy bajo en entrenamiento pero un error muy alto en validación.

4. ¿Qué representa la curva ROC, qué métricas van en sus ejes X e Y, y cómo se interpreta un área bajo la curva (AUC) de 0.5 frente a una menor a 0.5?

La curva ROC evalúa el desempeño de un clasificador probabilístico a distintos umbrales de decisión. En el eje X va la tasa de falsos positivos (FPR = FP / (FP + TN) = 1 - Especificidad) y en el eje Y va la tasa de verdaderos positivos (TPR = TP / (TP + FN) = Recall). Un AUC de 0.5 equivale a un clasificador aleatorio, mientras que un AUC menor a 0.5 indica que el modelo es peor que el azar pero es excelente prediciendo la clase opuesta, por lo que basta con invertir las predicciones.

5. ¿En qué se diferencian los esquemas de validación K-Fold Cross Validation y Stratified K-Fold?

K-Fold divide el conjunto de datos de entrenamiento en K partes iguales al azar para iterar K veces rotando el bloque de validación. Stratified K-Fold realiza esa misma partición pero asegurando que cada uno de los K bloques mantenga exactamente la misma proporción de clases que el conjunto de datos original, lo cual es crucial para datos desbalanceados.

6. Si al entrenar un clasificador observas un 99% de exactitud en el conjunto de entrenamiento pero solo un 61% en el conjunto de validación, ¿qué problema presenta el modelo y cuáles son dos soluciones sugeridas en clase?

El modelo presenta sobreentrenamiento (overfitting o alta varianza). Dos soluciones explicadas en clase son agregar más datos de entrenamiento y aplicar técnicas de regularización (o dropout / parada temprana).

7. ¿Qué es la fuga de datos (Data Leakage) por preprocesamiento y por qué produce métricas engañosas?

Ocurre cuando se aplican transformaciones como estandarización, normalización o PCA utilizando las estadísticas (media o desviación) de todo el conjunto de datos antes de separar el conjunto de prueba. Esto contamina el entrenamiento porque el modelo adquiere información del conjunto de prueba que no debería conocer, generando métricas artificialmente optimistas que colapsan en producción.

8. ¿Qué es el Data Drift, por qué el profesor afirmó que el modelo degrada silenciosamente y cuál es la solución cuando ocurre?

El Data Drift es el cambio de las características estadísticas de los datos en producción respecto a la distribución con la que el modelo fue entrenado. Se degrada silenciosamente porque el modelo no falla de golpe sino que sus predicciones pierden precisión gradualmente conforme el mundo cambia; la solución es detectar la desviación contra la distribución de referencia y reentrenar el modelo desde cero.

Puntos clave

  • PCA es no supervisado (maximiza varianza); LDA es supervisado (usa etiquetas, maximiza separabilidad entre clases).
  • Error Tipo I (falso positivo) = alarma sin incendio; Error Tipo II (falso negativo) = incendio sin alarma — normalmente el más grave.
  • Si la curva ROC cae bajo la diagonal, el modelo no es inútil: basta con invertir la predicción para volverlo excelente.
  • K-Fold se aplica solo dentro de entrenamiento/validación, nunca tocando el conjunto de prueba reservado.
  • Data drift se combate reentrenando desde cero con una ventana móvil de datos recientes, no acumulando todo el histórico.
