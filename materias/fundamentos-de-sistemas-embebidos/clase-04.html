Microarquitectura del Pentium (P5): pipeline superescalar U/V y distribución estadística de instrucciones

Tras el litigio con AMD, Intel abandonó la nomenclatura numérica y desarrolló la arquitectura P5, dando origen al procesador Pentium en 1993 a 200 MHz. El Pentium introdujo una microarquitectura superescalar con doble pipeline de ejecución: el pipeline U (principal) es capaz de ejecutar cualquier instrucción del catálogo x86, incluyendo cómputo pesado en la FPU; el pipeline V (secundario) está optimizado exclusivamente para instrucciones simples de carga, almacenamiento y manipulación de índices en memoria.

Esta separación se apoya en un dato estadístico que el profesor marcó como examinable: en cualquier programa compilado, entre el 60 % y el 75 % de las instrucciones son operaciones simples de carga y almacenamiento (load/store) para mover datos entre registros y memoria; solo entre el 25 % y el 40 % corresponde a cómputo matemático pesado (FPU, derivadas, integrales, funciones trigonométricas, multiplicación de matrices o evaluación de funciones sigmoides para IA). Esta distribución fundamenta el uso de pipelines dobles: mientras el pipeline U procesa una instrucción pesada de FPU (que puede tomar varios ciclos), el pipeline V ejecuta en paralelo múltiples instrucciones simples de lectura/escritura, maximizando el uso de los transistores disponibles.

Herramientas de compilación — el toolchain GCC en sistemas embebidos

En el desarrollo de sistemas embebidos se usa el toolchain de GNU GCC desde terminal:

  • Compilación directa: gcc programa.c -o ejecutable produce el binario final (o a.out si se omite -o).
  • Generación de archivo objeto (-c): gcc -c modulo1.c genera modulo1.o. Se usa en automatizaciones con make o cmake para compilaciones incrementales — la herramienta compara la fecha de modificación del .c contra la del .o; si el origen es anterior, omite la recompilación. El profesor lo resumió con la frase: "compilar es caro, checar fechas es gratis."
  • Generación de ensamblador (-S): gcc -S programa.c produce programa.s en ensamblador legible, para que el ingeniero inspeccione la generación de código a nivel de registros, evalúe la eficiencia de las instrucciones que dictó el compilador y verifique la ocupación real del procesador.
  • El enlazador (ld): toma todos los archivos objeto (.o) y librerías para construir el ejecutable final.
Ejemplo de reducción algorítmica: el Cierre Convexo (Convex Hull)

Para ilustrar la importancia de la manipulación eficiente de memoria, el profesor usa el problema del Cierre Convexo en geometría computacional: dado un conjunto de puntos en un plano, encontrar el contorno que los delimita. La evaluación por fuerza bruta de una nube de puntos tiene complejidad O(Nᴺ) u O(N²); el algoritmo se puede reducir a su cota inferior O(N log N) si los puntos se ordenan previamente en el plano. Dado que los algoritmos de ordenamiento (Heapsort, Mergesort, Bubble sort) consisten en casi un 95 % de operaciones de comparación, carga, almacenamiento e incremento de índices, esta reducción de complejidad algorítmica se resuelve mediante gestión eficiente de memoria, sin saturar la ALU ni la FPU — es decir, se apoya en el mismo pipeline de instrucciones simples (U/V) descrito arriba.

Alineación de memoria y empaquetado de estructuras (struct packing)

En arquitecturas modernas de 64 bits, la RAM no se direcciona byte por byte de forma aislada, sino en palabras de 8 bytes (64 bits). Al definir una estructura estándar en C:

struct Datos {
    int a;    // 4 bytes nominales
    int b;    // 4 bytes nominales
    double c; // 8 bytes nominales
};

aunque la suma teórica de los tipos primitivos es 4+4+8 = 16 bytes, el compilador asigna una palabra completa de 8 bytes a cada miembro para alinearlos con el bus de 64 bits, insertando bytes de relleno (padding). Como resultado, la estructura ocupa 24 bytes en RAM. Para transmitir esta estructura de forma contigua por un bus serie o una interfaz de red sin enviar bytes vacíos, se aplica la directiva de empaquetado:

struct Datos {
    int a;
    int b;
    double c;
} __attribute__((packed));  // Ahora ocupa exactamente 16 bytes
MMX, memorias DDR, y la llegada de SSE

En 1997 se introdujo MMX (Multimedia Extensions) en los procesadores Pentium: una extensión SIMD (Single Instruction Multiple Data) que añade un registro vectorial de 64 bits, compartido físicamente con la FPU, manipulable dinámicamente como 8 variables char, 4 short, 2 int o 1 long. La arquitectura MMX incorporó un pipeline de 5 etapas, 32 KB de caché L1 y 57 nuevos mnemónicos (llegando a un catálogo de unas 43,000 instrucciones), pensados para acelerar la interfaz gráfica de Windows 95 y el renderizado 2D.

En este mismo periodo surgieron las memorias DDR (Double Data Rate), que duplican el ancho de banda efectivo transfiriendo datos tanto en el flanco de subida como en el de bajada de la señal de reloj, sin ensanchar el bus físico.

El Pentium II (1997, 450 MHz, núcleo P6) refinó la ejecución de código de 16 bits. En 1999 se lanzó el Pentium III (1 GHz+), que introdujo SSE (Streaming SIMD Extensions) para reemplazar a MMX: SSE añadió 8 registros independientes de 128 bits (registros XMM), desvinculados de la FPU, con 70 nuevas instrucciones vectoriales pensadas para procesamiento 3D.

Pentium Pro (P6) — el salto a ejecución fuera de orden

El Pentium Pro (1995) introdujo la microarquitectura de sexta generación P6, orientada a servidores. Sus innovaciones principales:

  • PAE (Physical Address Extension): extiende el bus de direcciones a 36 bits para direccionar hasta 64 GB de RAM, manteniendo los registros internos y el espacio lógico en 32 bits.
  • Pipeline de 14 etapas, con 3 decodificadores en paralelo (1 decodificador IA-32 completo y 2 decodificadores simples) capaces de procesar 3 microoperaciones simultáneas.
  • Microoperaciones (µ-ops): el núcleo P6 funciona internamente como una arquitectura RISC — las instrucciones CISC complejas de alto nivel se descomponen en microoperaciones RISC elementales que se ejecutan en paralelo sobre el pipeline.
  • Ejecución fuera de orden (Out-of-Order Execution): el procesador reordena dinámicamente las instrucciones entrantes para ejecutar primero aquellas cuyos datos ya están disponibles en caché, aprovechando ciclos de reloj que de otro modo quedarían inactivos.
  • Ejecución especulativa: evaluación anticipada de ramas de código antes de confirmar si serán necesarias.
  • Renombrado de registros (Register Renaming): el hardware mapea los registros nominales (AX, BX…) hacia un banco de registros físicos mucho más grande en el silicio, permitiendo ejecutar varios hilos o programas de 16/32 bits de forma concurrente sin conflictos de dependencia.
Pentium 4 y NetBurst — cuando más frecuencia no significa más rendimiento

En el año 2000, Intel lanzó el Pentium 4 basado en la arquitectura NetBurst. NetBurst implementó un pipeline de más de 20 etapas, diseñado para alcanzar frecuencias teóricas de hasta 10 GHz. Sin embargo, la arquitectura sufrió severos problemas de disipación térmica — procesadores de 400 W que, dada la baja eficiencia (~60 %) de los transformadores de la época, requerían fuentes de poder de hasta 1.4 kW — y ofrecía un rendimiento por ciclo inferior al del propio Pentium III o a los procesadores AMD Athlon de la competencia.

La segunda guerra de los 64 bits: Intel Itanium (IA-64) vs. AMD Opteron (AMD64)

El límite de 4 GB de RAM de las arquitecturas de 32 bits obligó la transición a los 64 bits. Intel desarrolló la arquitectura Itanium (IA-64) entre 1989 y 2001: un diseño de 64 bits mononúcleo completamente nuevo que rompió la retrocompatibilidad binaria con x86 (IA-32). Adoptar Itanium exigía a las empresas recompilar e invertir en nuevos desarrollos de software y sistemas operativos — resultó en un fracaso comercial.

En 2003, AMD lanzó el Opteron con la arquitectura AMD64 (x86-64), que ofrecía 64 bits con retrocompatibilidad nativa total para Modo Real (8086), Modo Protegido (286/386), Modo Virtual y Modo Largo (64 bits). La comparación de segunda generación entre ambas arquitecturas:

El éxito comercial de AMD64 obligó a Intel a licenciar la arquitectura de 64 bits de AMD e integrarla en sus propios procesadores bajo la denominación Intel 64 / x86-64.

Puntos clave

  • Pipeline superescalar U/V del Pentium: se apoya en que 60–75 % del código compilado son operaciones simples de load/store, dejando solo 25–40 % para cómputo FPU pesado.
  • Alineación de memoria (struct packing): en 64 bits la RAM se direcciona en palabras de 8 bytes; el padding infla una struct de 16 a 24 bytes salvo que se use __attribute__((packed)).
  • Pentium Pro (P6): introduce ejecución fuera de orden, ejecución especulativa y renombrado de registros — mecanismos que perduran en los procesadores modernos.
  • MMX → SSE: de un registro de 64 bits compartido con la FPU a 8 registros XMM de 128 bits independientes, pensados primero para 2D (Windows 95) y luego para 3D.
  • IA-64 fracasó por romper la retrocompatibilidad; AMD64 triunfó por mantenerla — Intel terminó licenciando la arquitectura de 64 bits de su propio rival.
