Las tres tareas y el flujo del proceso

  • Regresión — modela cómo las variables independientes afectan a una variable numérica (p. ej. relación entre ventas y demanda). Explica el efecto de cada variable sobre el producto.
  • Agrupamiento / clustering — identifica grupos de productos o sucursales con comportamiento semejante; analiza tendencias por sucursal.
  • Clasificación — asigna categorías (p. ej. clasificar la demanda de una sucursal en alta, baja o media). Los árboles de decisión ayudan a prever si un día tendrá alta demanda para preparar la producción.

Cadena de valor: datos crudos → modelos → patrones → predicciones → mejores decisiones.

Datos internos y externos (ejemplo: los pastes de Pachuca)

  • Internos (dependen de la empresa): fecha, producto, cantidad vendida, precio, sucursal, inventario, promociones.
  • Externos (factores ajenos): calendario de días festivos, clima (el antojo de pastes calientes sube con el frío de Pachuca), eventos especiales.

Fases de preparación de datos

  • Limpieza. Eliminar duplicados con una regla de unicidad: combinar campos que identifican la transacción (fecha + lugar + tipo de compra) para detectar redundancias por fallas eléctricas o respaldos. Los valores faltantes (captura manual, fallas de equipo) se tratan con extrapolación estadística o eliminación directa del registro.
  • Outliers (valores atípicos). No son errores: son eventos con condiciones distintas a las normales (p. ej. un pico de ventas de pastes cuando juegan "Los Tuzos" en Pachuca). Se identifican y se les da un tratamiento aparte.
  • Transformación. Adecuar los datos para que los modelos sean más eficientes:
    • Generalización: agrupar días en semanas, meses o años.
    • Suavizado: reducir picos agudos para analizar la distribución.
    • Normalización: escalar los valores numéricos a un rango fijo, típicamente [0, 1].

Validación (según el tipo de modelo)

  • Regresión: error de estimación ≤ 10 % para evitar mermas o sobreproducción.
  • Clustering: que las agrupaciones por sucursal sean consistentes con el comportamiento típico de esa sucursal.
  • Modelo de operación: que cubra correctamente la demanda alta, media y baja.

Tema 2 — Arquitectura de minería de datos (arranque)

Minería de datos (definición formal del profesor): "proceso de análisis de grandes conjuntos de datos". Los datos son "la carnita, la esencia, el argumento" de cualquier análisis o decisión industrial.

Ecosistema heterogéneo: las empresas operan con un "mix de tecnologías": AWS, Google Cloud, Azure, SAP, bases relacionales (Oracle, SQL Server), Excel, y entornos analíticos masivos (Hadoop, Data Warehouses). Hoy ≈ 70 % de la información corporativa global vive y se procesa en la nube; la migración va de servidores locales (on-premises) a Data Warehouses y Data Lakes en la nube.

Taxonomía de bases de datos especializadas:

  • Blockchain — base de datos de cadena de bloques.
  • Espaciales — coordenadas, distancias y áreas geográficas en tiempo récord (mapas, logística).
  • Columnares — lectura/escritura analítica masiva a gran velocidad (p. ej. Amazon Redshift); surgieron hace ~15–20 años ante los límites de las relacionales; soportan transacciones críticas con Two-Phase Commit.
  • Gráficas.
  • Documentales — grandes volúmenes de documentos (historiales médicos, leyes, periódicos, libros) con búsqueda conceptual inmediata.
  • Series de tiempo.
  • Vectoriales — textos, archivos e imágenes representados como vectores; búsquedas de similitud muy veloces (a qué imágenes se parece una imagen de entrada); base de la IA moderna.
  • En memoria (in-memory) — toda la base reside en RAM en vez de disco → velocidad muy superior.

Arquitectura de datos, seguridad y repositorios

  • Arquitectura de base de datos: el diseño de esquemas y diagramas que integran redes, servidores y conexiones para mapear cómo fluyen, se integran y se rescatan los datos que alimentan los modelos.
  • Gobernanza de seguridad (gran avance en los últimos 15 años): acceso restringido por usuario y hasta por columna (un analista ve nombres de empleados pero no salarios), por horario (p. ej. solo de 9:00 a 10:00), firewalls y auditoría automática con alarmas ante cualquier intento de alterar transacciones.
  • Acceso en tiempo real: imprescindible en finanzas, retail, análisis bursátil y sensores IoT, donde el retraso impide reaccionar al mercado.
  • Repositorio de datos: contenedor (físico o digital, local o global) que almacena grandes volúmenes con estructura y jerarquía definidas, con metadata obligatoria y control de acceso estricto para administrar, auditar y analizar el ciclo de vida de la información.
    • Base de datos relacional (Access, SQL Server local): esquema de tablas y relaciones, normalmente hasta gigabytes, enfoque transaccional inmediato.
    • Repositorio: concepto más macro (servidores de archivos, data lakes, contenedores); estructurado y no estructurado; terabytes o petabytes; acceso concurrente de miles de usuarios; registro histórico masivo.
