Mtro. Juan Ángel Calvillo Pérez · 9 sep 2026 · Definición de metodologías de trabajo (Scrum vs. Cascada) y especificación de proyectos de infraestructura con virtualización: requerimientos funcionales/no funcionales, reglas de VMs cruzadas y detalle de las 10 propuestas de proyecto.

En corto

  • Scrum: entregas semanales de incrementos potenciales de valor, registro diario de experimentos/impedimentos y mínimo dos actualizaciones semanales en Git.
  • Cascada: alcance y requerimientos documentados de forma rígida desde el inicio; no se permite modificar módulos a mitad del proyecto.
  • Arquitectura obligatoria: mínimo 2 a 3 máquinas virtuales cruzando sistemas operativos cliente-servidor (Windows/Linux).
  • RF vs. RNF: los funcionales definen qué hace el sistema; los no funcionales, sus métricas de rendimiento y tiempo de respuesta.
  • Entregables finales: manual técnico, manual de usuario y video demostrativo de instalación (máximo 15 minutos).
  • Evaluación: operativa y en vivo ante el profesor, con preguntas individuales a cualquier integrante del equipo.
  • Prohibición: no se permite usar Microsoft SQL Server en proyectos de servidor web, por licenciamiento.

🎯 Para el examen

  • RF vs. RNF con ejemplo: RF — "El sistema deberá registrar la entrada de un vehículo"; RNF — "El sistema deberá responder en un tiempo máximo definido".
  • Historias de usuario (Scrum) vs. RF/RNF + casos de uso (Cascada): Scrum organiza por prioridad (alta/media/baja) en tablero; Cascada define fases formales con diagramas de casos de uso.
  • Control formal de cambios en Cascada: toda modificación requiere justificación, análisis de impacto y actualización completa de la documentación.
  • Estudio del estado del arte: obligatorio en Cascada cuando no hay datos económicos para un estudio de factibilidad financiera.
  • Evidencia en Git (Scrum): mínimo dos días de trabajo/revisión y dos modificaciones semanales verificables en el historial.
  • Regla de heterogeneidad de SO: servidor Windows Server → cliente Linux; servidor Ubuntu Server → cliente Windows.
  • Restricción de licenciamiento: SQL Server prohibido para servidores web con base de datos.
Metodologías de desarrollo: Scrum vs. Cascada

Scrum (agilidad e incrementos):

  • Ciclo de trabajo: organizado en sprints semanales, con entrega continua de "incrementos potenciales". El profesor enfatizó que pasar de "Hola Mundo" a "Hola Mundo Juan" NO constituye un incremento potencial.
  • Artefactos requeridos: ficha de inicio, visión del producto, product backlog, historias de usuario con criterios de aceptación, sprint backlog.
  • Historias de usuario (ejemplos): H1 — Registrar vehículo (prioridad alta); H2 — Consultar espacios disponibles (prioridad alta); H5 — Calcular costo de estancia. Se organizan en tableros por prioridad (alta/media/baja).
  • Seguimiento y Git: reuniones diarias enfocadas en verificar objetivos; bitácora de experimentos para registrar impedimentos (falta de licencias, problemas de configuración, límites de RAM). El progreso se audita en Git, exigiendo mínimo dos modificaciones semanales.

Cascada (enfoque tradicional):

  • Definición inicial: todo el alcance y requerimientos quedan documentados formalmente desde el principio; no se permiten cambios arbitrarios durante el desarrollo (ej. cambiar un modelo de red neuronal por un chatbot a medio proyecto).
  • Etapas secuenciales: definición de solución → desarrollo → pruebas → implementación.
  • Documentación exigida: planteamiento del problema, objetivos, alcances, estudio de factibilidad (o estudio del estado del arte si no hay datos financieros), especificaciones RF/RNF, diagramas de casos de uso, diseño del sistema y bases de datos, plan y casos de prueba, acta de control de cambios.
  • Revisiones del semestre: inicial (acuerdo de alcance) · intermedia (verificación de avance real y control formal) · final.
Requerimientos funcionales (RF) y no funcionales (RNF)
  • RF (Requerimientos Funcionales): definen comportamientos directos del sistema. Ej.: "RF1: El sistema deberá registrar la entrada de un vehículo"; "RF2: El sistema deberá registrar la salida de un vehículo".
  • RNF (Requerimientos No Funcionales): miden calidad o restricciones operativas. Ej.: "RNF1: El sistema deberá responder en un tiempo máximo definido".
Especificaciones de infraestructura para los proyectos
  • Entorno virtualizado: obligatorio 2 a 3 VMs por proyecto (o hardware dedicado equivalente, ej. Raspberry Pi, si se justifica).
  • Sistemas operativos permitidos: Ubuntu Server o Windows Server como base.
  • Cruce de SO: servidor Windows Server exige cliente Linux; servidor Ubuntu Server exige cliente Windows.
  • Ejes de evaluación: configuración de red, gestión de servicios, seguridad, evidencias de funcionamiento.
Las 10 propuestas de proyecto (detalle técnico)
  1. Intranet empresarial: servidor DNS y dominio interno; Apache con virtual hosts; HTTPS (SSL/TLS); documentación de direccionamiento IP y archivos de configuración.
  2. Servidor de correo electrónico empresarial: DNS con dominio corporativo (ej. juanito@empresa.com); protocolos SMTP, POP3, IMAP; creación de usuarios, autenticación, cifrado TLS/SSL.
  3. Servidor de acceso remoto seguro: SSH con llaves criptográficas; administración de usuarios/grupos/permisos; SFTP; políticas de seguridad.
  4. Servidor de archivos empresariales: Samba y NFS; grupos por departamento (administración, ventas, sistemas, público) con permisos de lectura/escritura/ejecución. Restricción: toda la administración por línea de comandos, sin interfaz gráfica.
  5. Servidor web con base de datos: frontend/backend con PHP, Java o Python; base de datos relacional o no relacional (SQL Server prohibido por licencias); DNS e HTTPS (nada de localhost:8080); CRUD completo.
  6. Servidor web con balanceo de cargas: arquitectura distribuida, proxy de balanceo apuntando a Web 1 y Web 2; publicación con DNS; pruebas de disponibilidad con servidor espejo (alta disponibilidad ante fallas).
  7. Infraestructura de servicios para una escuela: integración de DHCP, DNS, sitio web informativo y servidor de archivos Samba.
  8. Servidor web con HTTPS y seguridad: red virtual, certificados SSL/TLS migrando de HTTP a HTTPS, modelos de autenticación (plus por implementar 2FA).
  9. Servidor de archivos y acceso remoto multiplataforma: Samba + NFS + SSH + SFTP con permisos por departamento, interoperable entre Windows y Linux.
  10. Servidor proxy y control de accesos: proxy con reglas de filtrado, autenticación, triggers para bitácoras de auditoría de seguridad (usuario, fecha, hora, acciones, tiempo conectado).
