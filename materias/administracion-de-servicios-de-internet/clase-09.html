Ante la pregunta de qué puertos se habían detectado, los alumnos identificaron el 80 (HTTP) y el 443 (HTTPS), y mencionaron brevemente servicios como FTP.

Se analizó por qué importa la dirección IP obtenida en la auditoría: permite saber si los servicios web están concentrados en un solo servidor local o virtualizados en la nube. El profesor comentó que algunas universidades alojan sus páginas localmente con servidores como Apache o Tomcat. Reiteró que las herramientas de Metasploit no se usan con fines maliciosos, sino para recolección de información con propósitos académicos. En la terminal de Metasploit se trabaja con librerías auxiliares (auxiliary), la dirección objetivo se guarda en la variable RHOSTS (Remote Host) y la configuración se verifica con show options.

Explicado en simple

Kali Linux es como una caja de herramientas de un inspector de seguridad que contiene instrumentos para revisar cerrojos, y Metasploit es un dispositivo auxiliar dentro de esa caja para probar si las cerraduras de una casa responden.Dónde falla la analogía: La analogía falla porque en Kali Linux no tocas cerrojos físicos, sino que interactúas enviando paquetes de datos digitales a través de la red hacia variables como RHOSTS.

Por qué importa / con qué se conecta

Permite identificar si los servicios web de una organización están centralizados en un solo servidor local o virtualizados en la nube, evaluando la vulnerabilidad de la infraestructura.

Escaneo de encabezados HTTP y detección de infraestructura

Con Metasploit se analizaron los encabezados HTTP de servidores objetivo, como el del Politécnico (www.ipn.mx). El profesor preguntó por qué tomarlo de ejemplo y señaló que en implementaciones débiles o sin protección todos los servicios corren dentro de una sola máquina. Eso es un riesgo crítico de disponibilidad: si un atacante compromete o tira ese equipo, no hay redundancia ni respaldos activos.

Al ejecutar el módulo de escaneo de directorios y encabezados HTTP, el sistema devolvió un Error HTTP 404 (Not Found) y se quedó reintentando. Cuando el profesor preguntó qué estaba impidiendo el escaneo, los alumnos respondieron que la infraestructura está respaldada por la nube de Microsoft Azure, cuya protección perimetral filtra y bloquea las peticiones de Metasploit e impide navegar los directorios. Conclusión: en ese escenario Metasploit solo sirvió para identificar puertos abiertos, no para vulnerar la aplicación.

Explicado en simple

Es como enviar un cartero a tocar la puerta de una oficina para ver quién sale a responder y qué letrero tiene colgado en la recepción.Dónde falla la analogía: Deja de funcionar cuando la recepción tiene un guardia de seguridad privado en la nube que detiene al cartero en la entrada y le entrega una nota de error 404 en lugar de dejarlo pasar a los pasillos.

Por qué importa / con qué se conecta

Permite detectar si la infraestructura web está protegida por servicios en la nube como Microsoft Azure o Cloudflare, o si depende de un solo servidor centralizado sin redundancia.

Errores comunes: Pensar que si Metasploit devuelve un error HTTP 404 o se queda cargando significa que la herramienta falló, cuando en realidad refleja que la infraestructura de Azure está bloqueando el escaneo de directorios.

Detección de hosts y escaneo avanzado de puertos con Nmap

Tras ver las limitaciones de Metasploit en redes protegidas, el profesor presentó Nmap (Network Mapper) en la terminal de Kali. Escribir solo nmap muestra la sintaxis básica y exige una IP o un rango de red objetivo.

Antes de escanear se revisó la configuración de red propia con ip a (o ip addr). Interfaces que se explicaron:

  • eth0: interfaz Ethernet física o virtual, para el tráfico hacia la red local o internet.
  • lo (loopback): interfaz de bucle local, asociada a 127.0.0.1 (localhost), con la que el sistema se comunica consigo mismo.

En la práctica en vivo, la máquina virtual de Kali tenía la IP 192.168.139.132. El profesor explicó que el segmento 192.168.x.x corresponde a direcciones IP privadas de Clase C, muy usadas en virtualización y redes locales. Se ejecutaron estas modalidades de Nmap:

ComandoPropósito
nmap [IP]Escaneo básico de puertos TCP. En la prueba sobre el segmento de la máquina virtual detectó 4 hosts activos en 8 segundos, con puertos abiertos e interfaces como NetBIOS (puerto 445 de Microsoft) y direcciones MAC.
nmap -sn [IP/segmento]Ping sweep (descubrimiento de hosts): no escanea puertos, solo verifica qué dispositivos están encendidos (up) o apagados (down). Sirve para descartar IPs inactivas antes de un escaneo exhaustivo.
nmap [IP]/24Notación CIDR /24, equivalente a la máscara 255.255.255.0. Escanea las 254 direcciones del segmento de Clase C y reporta la latencia y las direcciones MAC de cada dispositivo.
nmap -sS [IP]SYN scan (escaneo sigiloso): envía paquetes TCP SYN y espera el SYN-ACK sin completar el saludo de tres vías (sin el ACK final). Así el escaneo no queda en los logs convencionales del servidor objetivo.
nmap -sV [IP]Detección de versión: determina la versión exacta del software o servicio en cada puerto abierto.
nmap -O [IP]Detección de sistema operativo: analiza las respuestas del stack TCP/IP para identificar el SO del host.
nmap -A [IP]Escaneo agresivo: combina detección de SO (-O), de versiones (-sV), scripts predeterminados (-sC) y traceroute. Da la mayor cantidad de información, pero es muy detectable.

Explicado en simple

Es como un radar que envía señales a todas las casas de una calle para saber cuáles están habitadas y qué puertas o ventanas tienen abiertas.Dónde falla la analogía: El radar común solo detecta objetos, mientras que Nmap puede enviar paquetes específicos TCP SYN sin completar el saludo de tres vías para saber qué sistema operativo y versión exacta de software corre en cada puerto.

Por qué importa / con qué se conecta

Es la herramienta fundamental de auditoría para mapear redes locales o privadas de Clase C (/24), identificar latencias, direcciones MAC y detectar puertos críticos abiertos como el 445 de NetBIOS o 3306 de MySQL.

Errores comunes: Confundir la interfaz de red Ethernet eth0 con la interfaz de loopback lo (127.0.0.1) que solo sirve para que el sistema hable consigo mismo, o no especificar la IP al ejecutar nmap.

Automatización de auditorías con Bash e integración con Python

El profesor explicó cómo automatizar estos procesos en la administración de servidores. Al preguntar qué es Bash, un alumno respondió que es un intérprete de terminal y una forma de ejecutar comandos automáticamente. El profesor confirmó que en Linux la programación a nivel de sistema operativo se hace con scripts (extensión .sh) que ejecuta el intérprete Bash.

Se planteó la estrategia de programar un script en Bash que lance un escaneo sigiloso (nmap -sS) con un temporizador (cron job o timer), por ejemplo cada hora, para auditar la red de forma constante y generar un reporte automático si se abre un puerto nuevo o aparece una vulnerabilidad. Además se destacó la integración con Python: un script conectado a las salidas de Nmap puede procesar los resultados y enviar alertas en tiempo real (por ejemplo, mensajes automáticos por WhatsApp o SMS) a los administradores cuando ocurra un evento crítico.

Explicado en simple

Es como contratar a un guardia nocturno robótico que recorre la red cada hora en silencio y te manda un mensaje de texto al celular si encuentra una puerta abierta.Dónde falla la analogía: Un guardia robótico recorre pasillos físicos, mientras que un script en Bash ejecuta comandos de Nmap en la consola mediante temporizadores y pasa la salida de texto a Python para procesar los datos.

Por qué importa / con qué se conecta

Permite mantener un monitoreo continuo y desatendido de los servidores para detectar vulnerabilidades en tiempo real sin requerir la presencia manual constante del administrador.

Por qué importa / con qué se conecta

Permite a cada estudiante profundizar en una herramienta real de hacking ético (como Medusa, Maltego, OpenVAS, John the Ripper o NetExec) generando evidencia práctica y documentación paso a paso.

🧠 Ponte a prueba

Intenta contestar cada pregunta antes de abrirla. Recordar por tu cuenta es lo que fija la información; releer no la fija.

1. ¿Cuáles son las dos interfaces de red que muestra el comando ip a en Kali Linux y qué función cumple la interfaz lo?

Muestra eth0 y lo. La interfaz lo (loopback) corresponde a la IP 127.0.0.1 y sirve para que el sistema operativo se comunique consigo mismo (localhost).

2. Explica con tus palabras por qué un escaneo de puertos con Nmap mediante el parámetro -sS se considera un escaneo sigiloso.

Porque envía paquetes TCP SYN y analiza la respuesta sin completar el saludo de tres vías (three-way handshake) con el paquete ACK final, evitando que la conexión quede registrada en los logs convencionales del servidor.

3. Si tu máquina virtual de Kali Linux tiene la IP 10.0.2.15/24 y quieres realizar un descubrimiento de hosts activos en todo ese segmento sin escanear sus puertos, ¿qué comando exacto de Nmap debes ejecutar?

Debes ejecutar nmap -sn 10.0.2.0/24 (o nmap -sn 10.0.2.15/24).

4. Compara la finalidad del parámetro -sV frente al parámetro -O en un escaneo de Nmap.

El parámetro -sV inspecciona los puertos abiertos para detectar la versión exacta del software o servicio que se ejecuta, mientras que -O analiza las respuestas del stack TCP/IP para identificar el sistema operativo instalado en el host.

5. En Metasploit, ¿qué variable de configuración se utiliza para definir la dirección IP del servidor objetivo antes de ejecutar un módulo auxiliar?

Se utiliza la variable RHOSTS (Remote Host) mediante el comando set RHOSTS [IP_objetivo].

6. Explica por qué el escaneo de directorios con Metasploit sobre el servidor del IPN devolvió un error HTTP 404 y no permitió vulnerar la aplicación.

Porque la infraestructura web del servidor está respaldada y protegida por la nube de Microsoft Azure, la cual filtra y bloquea las peticiones profundas de Metasploit provocando que la herramienta se quede reintentando sin acceder a los directorios.

7. Un administrador quiere auditar el servidor 192.168.1.50 para obtener la mayor cantidad posible de información automática (sistema operativo, versiones de servicios, scripts por defecto y traceroute). ¿Qué comando con escaneo agresivo debe ejecutar en Nmap?

Debe ejecutar nmap -A 192.168.1.50.

8. Compara la función de un script en Bash frente a un script en Python en el esquema de automatización de auditorías de red presentado en clase.

El script en Bash se encarga de programar y ejecutar periódicamente los comandos de Nmap a nivel de sistema operativo mediante temporizadores, mientras que el script en Python procesa los resultados de texto generados por Nmap para enviar notificaciones de alerta en tiempo real (como mensajes de WhatsApp o SMS).
