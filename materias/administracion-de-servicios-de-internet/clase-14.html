1 · Usuarios, roles y privilegios (y el error ORA-65096)
Qué es

La forma estándar de dar permisos en un gestor de bases de datos: los privilegios se agrupan en un rol y el rol se le asigna al usuario, en lugar de darle permisos sueltos a cada cuenta.

Explicado en simple

Es el gafete de una empresa: en vez de registrar la huella de cada empleado en cada puerta, haces un gafete de «Becario» con sus accesos ya programados y se lo das a quien entre como becario.Dónde deja de servir: un gafete se presta sin dejar rastro; en la base de datos cada sesión queda ligada a un usuario autenticado con contraseña.

Cómo funciona

El profesor entró a Oracle como administrador (SYSTEM) desde la consola sqlplus y creó un usuario:

CREATE USER Rafa IDENTIFIED BY 123;

En Oracle Enterprise esto puede dar ORA-65096: invalid common user or role name. Para corregirlo, primero se altera la sesión:

ALTER SESSION SET "_ORACLE_SCRIPT" = TRUE;

y se vuelve a ejecutar el CREATE USER, que ya funciona.

Luego preguntó: «¿Cuál es la manera correcta de hacer un usuario conforme al manejo de privilegios?». Un alumno contestó que se definía un contenedor con los privilegios, y el profesor lo aclaró: «Hago un usuario, luego serían los roles y al último los privilegios». Se crea el rol, se le dan los permisos y se le asigna al usuario:

CREATE ROLE becario;
GRANT CREATE SESSION   TO becario;
GRANT CREATE TABLE     TO becario;
GRANT INSERT ANY TABLE TO becario;
GRANT SELECT ANY TABLE TO becario;
GRANT CREATE TRIGGER   TO becario;
GRANT becario TO Rafa;
Por qué importa / con qué se conecta

Es como se segmentan las cuentas en un servidor real: nadie trabaja como administrador general. Se liga con la administración de cuentas que ya se ve en el proyecto Scrum (permisos en Samba y SSH del Sprint 3).

Errores comunes

Crear el usuario sin habilitar _ORACLE_SCRIPT (sale ORA-65096), o darle los privilegios directamente al usuario en lugar de empaquetarlos en un rol.

2 · Almacenamiento: el privilegio UNLIMITED TABLESPACE
Qué es

La cuota de almacenamiento dentro del table space (los archivos donde Oracle guarda físicamente los datos) que necesita un usuario para poder guardar filas.

Explicado en simple

Es el casillero del gimnasio: la membresía te deja entrar (conectarte, crear la tabla), pero hasta que no te dan un casillero no puedes dejar nada guardado.Dónde deja de servir: el casillero tiene un tamaño fijo; con UNLIMITED TABLESPACE el espacio crece según el disco del servidor.

Cómo funciona

Ya conectado como Rafa, el profesor creó una tabla de prueba (funcionó, porque el rol tiene CREATE TABLE):

CREATE TABLE reprobaditos (
  id             NUMBER(3),
  fecha_completa TIMESTAMP,
  fecha_corta    DATE,
  nombre         VARCHAR2(20)
);

Pero el primer INSERT falló:

INSERT INTO reprobaditos VALUES (1, SYSDATE, SYSDATE, 'Axel');
-- ORA-01950: no privileges on tablespace 'USERS'

Explicación del profesor: «Hay privilegios, y más cuando son de sistema operativo, que les debes asignar directamente al usuario. Hay unos que no pueden ir en rol». Aunque el rol tenga INSERT ANY TABLE, lo que toca el almacenamiento físico no se hereda por el rol. Se arregla entrando otra vez como administrador:

GRANT UNLIMITED TABLESPACE TO Rafa;

Con eso la inserción ya se guarda.

Por qué importa / con qué se conecta

En producción, quedarse sin cuota en el table space detiene las aplicaciones conectadas a la base.

Errores comunes

Creer que con INSERT o con un rol completo ya hay espacio para guardar.

3 · DATE frente a TIMESTAMP con SYSDATE
Qué es

Los dos tipos de dato de tiempo de Oracle que se compararon: DATE y TIMESTAMP (con fracciones de segundo), llenados con la función del sistema SYSDATE.

Explicado en simple

DATE, como se mostró en clase, es el calendario de pared: el día. TIMESTAMP es el cronómetro de carreras: hora, minuto, segundo y fracciones.

Cómo funciona

Con la inserción de arriba (SYSDATE en las dos columnas) y un SELECT * FROM reprobaditos;, la consola mostró la columna DATE solo como 19-OCT-26 y la TIMESTAMP con fecha, hora y fracciones de segundo.

Pregunta del profesor: «¿Para qué me sirve en un servidor de base de datos? ¿Creen que sirva tanta precisión?». Respuesta de la clase: si los datos cambian dentro del mismo segundo, o se pierde información de un segundo a otro, hay que poder rastrearla.

Un alumno preguntó si SYSDATE depende de la máquina local o se puede configurar de forma global. El profesor: se puede, pero no se recomienda centralizarlo en la base de datos; se basa en la zona horaria del lugar (en México la de referencia es la de Ciudad de México; México tiene tres zonas, Brasil dos o tres, Estados Unidos tres o cuatro) y centralizar hace perder esa información.

Nota (documentación de Oracle, no se dijo en clase): un DATE de Oracle sí guarda hora, minuto y segundo; lo que se vio en consola es solo el formato de despliegue por defecto. La diferencia real es que TIMESTAMP agrega fracciones de segundo (6 dígitos por defecto). En clase se habló de «nanosegundos».

Por qué importa / con qué se conecta

La auditoría necesita saber el orden exacto de transacciones casi simultáneas: por eso la tabla de auditoría usa TIMESTAMP.

4 · Table spaces, acceso usuario.tabla y COMMIT
Qué es

Cada usuario de Oracle tiene su propio esquema (el profesor lo dibujó como una carpeta por usuario). Para usar la tabla de otro hay que nombrarla con su dueño, y los cambios de datos solo los ven los demás después de un COMMIT.

Explicado en simple

Es un documento en tu carpeta: tu compañero solo lo encuentra si busca en tu carpeta, y solo ve tus cambios cuando le das «Guardar y publicar».Dónde deja de servir: un documento en la nube se sincroniza tecla por tecla; en la base de datos la transacción queda aislada hasta que la confirmas a propósito.

Cómo funciona

Se creó una segunda cuenta (CREATE USER Emilio IDENTIFIED BY 123;) con privilegios básicos. Desde ella:

SELECT * FROM reprobaditos;
-- ORA-00942: table or view does not exist

La tabla no es de esa cuenta, es de Rafa. Con el nombre calificado ya la encuentra:

SELECT * FROM Rafa.reprobaditos;
-- no hay filas seleccionadas

…pero sale vacía aunque Rafa ya había insertado. El motivo: los comandos DML (INSERT, UPDATE, DELETE) quedan en una transacción privada hasta que quien los hizo ejecuta COMMIT;. En palabras del profesor: «si no está publicado, no lo puedo ver».

En cambio, con DDL no hace falta: creó otra tabla (CREATE TABLE condicion (nombre VARCHAR2(30), sueldo NUMBER(6,2));) y mostró que DROP TABLE reprobaditos; tiene efecto inmediato sin COMMIT.

Por qué importa / con qué se conecta

Evita inconsistencias cuando varios usuarios o aplicaciones trabajan sobre la misma base.

Errores comunes

Olvidar el COMMIT y creer que los datos ya están guardados para todos; consultar la tabla de otro usuario sin el prefijo usuario..

5 · Auditoría con disparadores (triggers), :OLD y :NEW
Qué es

Un disparador es un bloque PL/SQL guardado en el servidor que se ejecuta automáticamente antes o después de un INSERT, UPDATE o DELETE sobre una tabla. Para auditar se usa para registrar quién, cómo y cuándo se modificaron los datos.

Explicado en simple

Es una cámara con sensor de movimiento sobre una caja fuerte: nadie la enciende; en cuanto alguien la abre, graba quién fue y a qué hora.Dónde deja de servir: la cámara solo ve desde afuera; el disparador además conoce el valor que había antes (:OLD) y el que se está guardando (:NEW).

Cómo funciona

Preguntó la diferencia entre procedimiento almacenado y disparador. Un alumno: «el trigger se activa con una acción; el procedimiento lo tienes que llamar tú». El profesor: «El disparador es automático y funciona antes o después de tres cosas: INSERT, UPDATE o DELETE. Se aterriza para auditar en el servidor: quién, cómo y cuándo lo hizo».

Primero la tabla de bitácora:

CREATE TABLE auditoria (
  usuario    VARCHAR2(30),
  movimiento VARCHAR2(30),
  fecha      TIMESTAMP
);

Luego el disparador sobre la tabla de trabajo, una vez por fila modificada:

CREATE OR REPLACE TRIGGER i_condicion
AFTER INSERT ON Rafa.condicion
FOR EACH ROW
BEGIN
  INSERT INTO auditoria VALUES (USER, 'inserto', SYSDATE);
END;
/

USER devuelve el nombre de la cuenta conectada que provocó el evento, sin pasarlo como parámetro. Se hicieron inserciones desde varias cuentas con nombres y «sueldos deseados» de los alumnos, y SELECT * FROM auditoria; mostró qué usuario hizo cada inserción y su sello de tiempo.

Para la práctica: el mismo disparador debe cubrir UPDATE y DELETE, usando los predicados INSERTING, UPDATING y DELETING y las variables de fila:

  • :NEW.campo — el valor que entra (en INSERT y UPDATE).
  • :OLD.campo — el valor que había antes y que se reemplaza o se borra (en UPDATE y DELETE).

La tabla de auditoría tiene que ampliarse para guardar el dato anterior y el nuevo.

Por qué importa / con qué se conecta

Es la base de la trazabilidad y de la prevención de fraudes en bases de datos empresariales; retoma la parte de seguridad que se vio con Kali (Clases 08 y 09).

Errores comunes

Escribir SHOW USER dentro del disparador en vez de la palabra reservada USER; olvidar FOR EACH ROW cuando se quiere una entrada por cada fila.

6 · SQL Developer local conectado a Oracle en la nube (Free SQL / Live SQL)
Qué es

Una conexión cliente-servidor por TCP/IP entre la herramienta gráfica local (SQL Developer) y una base de datos Oracle alojada en la nube, sin instalar el motor completo en tu máquina.

Explicado en simple

Es como una app de mensajería de escritorio: el programa corre en tu laptop, pero los datos viven en los servidores en internet.

Cómo funciona
  1. En la consola web de Free SQL / Live SQL, ir a la configuración de conexión.
  2. Copiar los parámetros: Host name, puerto (1521; o 2484 si es la conexión cifrada), nombre de servicio, usuario y la contraseña (botón «Regenerar password»).
  3. En SQL Developer: «Nueva conexión», capturar host y puerto, cambiar el tipo a Nombre de servicio (no SID) y poner usuario y contraseña.
  4. Probar y, si pasa, Conectar.

Desde SQL Developer local ejecutó CREATE TABLE pruebita (id NUMBER); y, al refrescar la consola en el navegador, la tabla ya aparecía en el servidor en la nube.

Por qué importa / con qué se conecta

Administrar infraestructura de datos remota sin consumir recursos locales; es parte del desarrollo que pide la práctica.

Errores comunes

Elegir «SID» en lugar de «Nombre de servicio».

🧠 Ponte a prueba
1. ¿En qué orden se configura correctamente la seguridad de acceso?

Usuario → rol (con sus privilegios) → asignar el rol al usuario. «Hago un usuario, luego serían los roles y al último los privilegios».

2. El rol tiene INSERT ANY TABLE y aun así sale ORA-01950. ¿Por qué y cómo se arregla?

Porque la cuota de almacenamiento en el table space no se hereda por un rol; hay que darla directo al usuario: GRANT UNLIMITED TABLESPACE TO Rafa;.

3. Otra cuenta hace SELECT * FROM reprobaditos; y sale «la tabla no existe». ¿Qué dos cosas hay que corregir?

Calificar con el dueño (SELECT * FROM Rafa.reprobaditos;) y que el dueño haga COMMIT para que sus inserciones sean visibles.

4. ¿Qué comando mostró el profesor que no necesita COMMIT, y por qué?

DROP TABLE: es DDL y tiene efecto inmediato.

5. Quieres auditar cambios de sueldo en empleados guardando el valor viejo y el nuevo. ¿Cómo armas el disparador?

AFTER UPDATE ON empleados FOR EACH ROW, insertando en la tabla de auditoría USER, la fecha, :OLD.sueldo y :NEW.sueldo (con columnas para ambos).

6. ¿Disparador o procedimiento almacenado: cuál se ejecuta solo?

El disparador, automáticamente ante INSERT/UPDATE/DELETE. El procedimiento hay que llamarlo explícitamente.

7. ¿Por qué la tabla de auditoría usa TIMESTAMP y no DATE?

Para distinguir y ordenar transacciones que ocurren dentro del mismo segundo; TIMESTAMP guarda fracciones de segundo.

8. ¿Qué datos necesitas para conectar SQL Developer a Free SQL?

Host name, puerto (1521, o 2484 cifrado), nombre de servicio, usuario y contraseña regenerada; tipo de conexión «Nombre de servicio».

9. ¿Cómo se arregla ORA-65096 al crear un usuario?

Con ALTER SESSION SET "_ORACLE_SCRIPT" = TRUE; y repitiendo el CREATE USER.
