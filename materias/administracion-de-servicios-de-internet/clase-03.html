En corto

  • Servidor = una computadora con hardware suficiente para atender peticiones de otros dispositivos y compartir procesamiento (software, hardware, dispositivos de red). No se define usando "modelo cliente-servidor" (redundancia circular).
  • Servidor vs. repositorio: el repositorio solo almacena datos (Git guarda scripts pero no los ejecuta); el servidor además ejecuta lógica (Python, SQL, redes neuronales, ML).
  • Pirámide DIC: Datos → (contexto) → Información → (matemáticas / algoritmos) → Conocimiento → decisiones.
  • Tríada CIA: Disponibilidad, Integridad, Confidencialidad.
  • Antes de instalar un servidor: levantamiento de requerimientos — de sistema (hardware/infra), funcionales (el qué), no funcionales (el cómo: velocidad, seguridad, usabilidad).
  • En la nube (Azure/AWS/GCP) todo el presupuesto y las alertas van en USD; nunca recomendar una nube sin análisis de requerimientos previo.

Qué es un servidor (y qué no)

Servidor: "un dispositivo que tiene la arquitectura suficiente para poder comunicar datos y peticiones por parte de otros dispositivos"; "una computadora que ofrece servicios para que otras accedan a información o herramientas, configurada de cierta manera, pero al final una computadora más". Tiene hardware potente para compartir servicios lógicos (software), físicos (hardware) y dispositivos de red. No se debe definir con el modelo cliente-servidor dentro de la propia definición (redundancia circular).

Servidor vs. repositorio: el repositorio solo almacena datos. En la práctica se usa una laptop de oficina (1 TB, 16 GB RAM) creyendo que es servidor cuando se comporta como repositorio pasivo. En un repositorio de Git subes scripts (Bash, Python, SQL), fotos o video, pero no se ejecutan. El servidor sí comparte procesamiento: correr Python, entrenar una red neuronal, simulaciones, IA y Machine Learning.

Pirámide DIC (Datos → Información → Conocimiento)

  • Datos — materia prima del repositorio. Estructurados (tablas) o no estructurados (archivos planos, fotos, video). Las BD guardan datos aislados.
  • Información — el analista le da contexto al dato (relevancia para el cliente).
  • Conocimiento — procesar la información con matemáticas, estadística, algoritmos y modelos predictivos para tomar decisiones.

Ejemplo (redes sociales): el usuario sube datos (fotos, publicaciones, interacciones) → la red extrae información (consume cierto contenido de 12:00 a 6:00 a. m.) → el conocimiento permite enviarle publicidad segmentada a esa hora.

Conectividad: cliente-servidor, intranet y CIA

  • BD cliente-servidor: el servidor almacena la BD y ejecuta el procesamiento pesado de las consultas; el cliente (p. ej. SQL*Plus) es solo un puente. Conexión mínima: una dirección IP + los protocolos de seguridad.
  • No hace falta internet: se puede montar una Intranet local (LAN / MAN / CAN / PAN) con cable cruzado, comprobar con ping y entrar por SSH (puerto 22).
  • Tríada CIA:
    • Disponibilidad — el servicio accesible de forma continua para el usuario autorizado, incluso en días de baja demanda (caso de la caída de BBVA Bancomer).
    • Integridad — los datos exactos y sin alteraciones no autorizadas (si el estado de cuenta dice $75, debe seguir diciendo $75).
    • Confidencialidad — solo quien tiene privilegios consulta; barrera contra externos; también protege los datos en tránsito.
  • Tramas: el paquete se fracciona en tramas, cada una con encabezado (header) y cola (footer), y viaja encriptada. Como los SMS antiguos (llegaba el bloque 2 de 3 antes que el 1 de 3) frente a WhatsApp, que retiene las tramas hasta tener el paquete completo.

Tipos de servidor de red

  • Web — entrega páginas por HTTP/HTTPS (puertos 80 y 8080).
  • De archivos — comparte documentos por FTP / SFTP.
  • De correo — envío y recepción de correo electrónico.
  • De base de datos / autenticación — datos estructurados y validación de accesos.

Levantamiento de requerimientos

El error más común es levantar un servidor sin definir un objetivo. Antes de instalar, se hace el levantamiento según el alcance:

  • De sistema — hardware, servidores, infraestructura, ancho de banda.
  • Funcionales — qué debe hacer el sistema (entradas, salidas, interacciones lógicas con el usuario).
  • No funcionales — estándares de calidad: eficiente, seguro, rápido (tiempo de respuesta corto), robusto, confiable, fácil de usar.
RequerimientoTipo
"El usuario debe loguearse antes de entrar al sistema"Funcional
"El tiempo de respuesta debe ser muy corto"No funcional
"Se necesitan múltiples servidores para garantizar la disponibilidad"De sistema
"Se requiere amplio ancho de banda para un video de streaming"De sistema
"Se debe enviar un mail con un informe al final de la semana"Funcional
"La interfaz debe ser sencilla y fácil de usar"No funcional

Aprovisionar servicios en la nube — Microsoft Azure

  • App Services + máquinas virtuales (VM). La asignación de usuarios y jerarquías se centraliza en el Active Directory; las VM se agrupan en grupos de recursos.
  • Nombre de la VM: identificador único sin espacios (ej. maquinita).
  • Nivel de seguridad: estándar → 2.ª generación → avanzada / alta confiabilidad. A más seguridad, más recursos → mayor costo.
  • Imagen de SO (Marketplace): Ubuntu Server, Oracle Linux, Windows Server 2025.
  • Directiva de desalojo (eviction policy): qué hacer con la VM y los datos si se suspende el pago — detener el servicio o eliminar todos los datos. Útil como mecanismo de ciberseguridad para no dejar rastro en crisis (fugas de personal, etc.).
  • Autenticación: clave pública SSH (SHA) o contraseña de texto plano (ejemplo inseguro: Juanito123).
  • Puertos de entrada (firewall): 22 SSH, 80 HTTP, 443 HTTPS.

Costos de almacenamiento y presupuestos en la nube

  • Variables de facturación: consumo (tiempo de CPU y memoria), almacenamiento (datos en reposo) y flujo de red (ingress / egress, con tres tipos de cargo). Analogía: rentar una bodega para guardar (barato) vs. una casa para vivir y consumir servicios (caro).
  • Niveles de acceso: Hot (acceso frecuente — almacenamiento caro, transacciones baratas) vs. Cool (respaldos infrecuentes — almacenamiento barato, acceso caro).
  • Enrutamiento: red privada de Microsoft (rápida y segura, más cara) vs. internet público (barato, seguridad a cargo del cliente).
  • Claves: usar customer-managed keys para que Microsoft no tenga acceso a los datos confidenciales.
  • Presupuestos y alertas: solo en USD, mensuales / trimestrales / anuales. Alertas por costo real (ej. 50 % = 0.50 de $5 000 = $2 500) y por costo previsto (predictivo, ej. 0.40).
  • Escalabilidad dinámica: contratar almacenamiento/cómputo masivo solo en picos (Buen Fin, diciembre) y cancelarlo después.
