En corto

  • DNS: traductor de nombres de dominio a IPs (como agenda telefónica).
  • DHCP: asignación automática de IPs, máscaras de subred, gateways y servidores DNS a clientes de red.
  • Proceso DORA: Discover (broadcast) → Offer (servidor responde) → Request (cliente acepta) → Acknowledge (confirmación).
  • 6 componentes: Ámbito (rango de IPs) · Tiempo de concesión · Puerta de enlace · Servidor DNS · Reservas (fijas por MAC) · Exclusiones (no asignar).
  • Riesgos: DoS por agotamiento de IPs · Servidores DHCP falsos (Rogue DHCP) · inyección SQL · DMZ/VPN como defensa.
  • Servidores: ISC DHCP (descontinuado 2022) → Kea DHCP (sucesor: JSON, multihilo, APIs).
  • Configuración de red en VM: la IP de la VM debe estar en la MISMA subred que el DHCP para que funcione.

Relación entre DNS y DHCP
  • DNS (Domain Name System): traductor de red que convierte nombres de dominio legibles en direcciones IP numéricas (equivalente a una agenda de contactos telefónicos). Ejemplo: `google.com` → `142.251.32.110`.
  • DHCP (Dynamic Host Configuration Protocol): protocolo de configuración dinámica de hosts encargado de asignar de manera automática direcciones IP, máscaras de subred, puertas de enlace y servidores DNS a los clientes de una red.
  • Necesidad histórica: evolución desde asignación manual (centrales telefónicas de conmutación manual) hasta automatización con servidores de red.
Ventajas de DHCP y el proceso DORA

Ventajas operativas en empresas:

  • Manejo automático de direccionamiento dinámico ante saturación de dispositivos en redes domésticas, corporativas e IoT (15–50 dispositivos en un hogar moderno).
  • Reducción de costos de personal técnico (no hay administración manual).
  • Eliminación de bitácoras manuales y prevención de conflictos por duplicidad de direcciones IP.

Proceso DORA — cuatro etapas del ciclo de concesión de una IP:

  1. Discover: cliente envía un mensaje de difusión (broadcast) en la red buscando un servidor DHCP activo.
  2. Offer: servidor DHCP responde al cliente ofreciéndole una dirección IP disponible dentro de su rango.
  3. Request: cliente acepta formalmente la oferta y solicita el uso de la dirección IP entregada.
  4. Acknowledge: servidor confirma la concesión y entrega la configuración completa de red al cliente (mascara, gateway, DNS).

Analogía universitaria: la red RIU requería credenciales y asignación manual previa; la red PC Puma opera mediante DHCP (DORA), liberando dinámicamente las IPs cuando los usuarios se desconectan.

Seguridad y riesgos en DHCP
  • Ataque DoS por agotamiento de DHCP: un atacante solicita masivamente direcciones IP ficticias hasta agotar el ámbito del servidor, impidiendo que dispositivos legítimos obtengan acceso a la red.
  • Servidor DHCP falso (Rogue DHCP): servidor no autorizado introducido en la red por un atacante para distribuir direcciones IP y servidores DNS fraudulentos, interceptando tráfico o desviando clientes.
  • Otras vulnerabilidades: inyección SQL, envenenamiento de caché.
  • Defensas: DMZ (zona desmilitarizada), VPNs, firewalls, políticas de seguridad.
6 componentes de configuración de DHCP
  • Ámbito (Scope): rango o segmento continuo de direcciones IP que el servidor está autorizado a entregar (ej. de `192.168.1.100` a `192.168.1.200`).
  • Tiempo de concesión (Lease time): periodo temporal durante el cual un cliente puede usar la IP asignada antes de renovarla o ser liberada.
  • Puerta de enlace (Gateway/Router): dirección IP de la interfaz del router para encaminar paquetes hacia redes externas.
  • Servidor DNS: direcciones IP de servidores de nombres asignados a los clientes para resolución de dominios (ej. `8.8.8.8` y `8.8.4.4`).
  • Reservas: asignación estática vinculada permanentemente a la dirección MAC del adaptador de red de un dispositivo (mismo cliente, siempre la misma IP).
  • Exclusiones: direcciones o rangos dentro del ámbito que se reservan y NO se asignan automáticamente (ej. `127.0.0.1`, direcciones fijas de servidores).
ISC DHCP vs. Kea DHCP — Evolución
  • ISC DHCP Server: servidor DHCP clásico desarrollado por Internet Systems Consortium (ISC), cuyo mantenimiento oficial finalizó a finales de 2022.
  • Kea DHCP Server: sucesora moderna de ISC DHCP; ofrece:
    • Soporte para IPv4 e IPv6.
    • Archivos de configuración en formato JSON (fácil de automatizar).
    • Arquitectura multihilo.
    • Integración con APIs.
    • Recomendación: usar versión estable 2.4 en producción (evitar 2.6/beta).
Práctica de laboratorio — Servidores DHCP en Linux

Requisito crítico: la dirección IP asignada a la VM debe pertenecer obligatoriamente a la MISMA subred configurada en el servidor DHCP (ej. si DHCP está en 192.168.1.0/24, la VM debe tener una IP en ese rango). De lo contrario, el servicio no arranca.

Parte A: ISC DHCP Server (descontinuado, pero aún usado)

# Instalación
sudo apt update
sudo apt install isc-dhcp-server

# Edición de /etc/dhcp/dhcpd.conf
subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.1.100 192.168.1.200;
  option routers 192.168.1.1;
  option domain-name-servers 8.8.8.8, 8.8.4.4;
  default-lease-time 600;
  max-lease-time 7200;
}

# Especificar interfaz en /etc/default/isc-dhcp-server
# (ej. eth0, enp0s3)

# Reinicio y verificación
sudo systemctl restart isc-dhcp-server
sudo systemctl status isc-dhcp-server
