Repaso de arquitectura (dado en clase)

El procesador ejecuta el algoritmo y los datos que están juntos en la memoria principal. El profesor lo describe como "un adminículo electrónico que ejecuta máquinas de Turing".

Modelo de Von Neumann — compatible con la máquina de Turing. Componentes básicos: controlador (genera las señales de activación), registro de estado, registro de propósito general, contador de programa (PC), ALU y una sola unidad de almacenamiento que contiene programa + datos + pila.

Cuello de botella de Von Neumann: ejecuta "de un pasito a la vez". El procesador va a memoria, jala la instrucción (fetch), la decodifica, vuelve a memoria por los datos, los procesa en la ALU y escribe el resultado. Mientras una fase ocurre, las demás unidades y buses están inactivos (al leer la instrucción, el decodificador y la ALU no hacen nada).

Modelo Load-Store (Peterson): demuestra que cualquier programa se puede reescribir con más instrucciones cortas basadas solo en carga y almacenamiento usando una ALU simple.

Arquitectura Harvard RISC: soluciona el cuello de botella separando físicamente instrucciones y datos: la cinta única de Turing se parte en dos — instrucciones (solo lectura) y datos (lectura y escritura) — permitiendo leer y escribir a la vez.

Segmentación (pipelining): 4 etapas que corren concurrentes por ciclo de reloj — Fetch → Decode → Execute → Write Back. Tras el arranque sale una instrucción por ciclo:

       T1    T2    T3    T4    T5    T6    T7
I1     F     D     E     WB
I2           F     D     E     WB
I3                 F     D     E     WB
I4                       F     D     E     WB
                         └── desde aquí: 1 resultado por ciclo

DirectorioPrioridadPara qué sirve
/—Raíz de toda la estructura de carpetas.
/bootaltaArranque del sistema operativo y almacenamiento del kernel.
/binaltaComandos binarios esenciales que todos los usuarios pueden ejecutar (cd, ls).
/devaltaDispositivos: todas las conexiones de hardware interno y externo; configuración de drivers (impresoras, escáneres, discos).
/etcaltaArchivos de configuración del SO y de las aplicaciones instaladas.

/tmpbajaTemporales. A diferencia de /var, lo borrado en /tmp se puede recuperar con un script de Bash mientras no se reinicie: al reiniciar, la RAM se desenergiza y esos espacios se marcan como libres.
/opt—Software adicional instalado por un usuario común (no por el administrador).
/proc—(mencionado) Información de procesos del kernel.

Terminal — localización y ayuda 
whereis ls      # ruta completa del paquete + sus directorios de config
                # (útil para migraciones)   ej. -> /usr/bin/ls
which ls        # SOLO la ruta del archivo ejecutable
pwd             # directorio actual (print working directory)
man ls          # manual local del comando (funciona sin internet)
                # salir con  q   [en clase se dijo Ctrl+Z, que en realidad SUSPENDE el proceso]

⚠️ Examen: distinguir whereis (mapea toda la carpeta de instalación, documentación y binarios — para migraciones) de which (solo localiza el binario ejecutable).

Terminal — procesos 
ps              # procesos de esta terminal: PID, terminal, TIME, comando
kill <PID>       # termina un proceso
ps aux          # TODOS los procesos del sistema (incluidos los del kernel)
                #   a = procesos de todos los usuarios
                #   u = uso de recursos (columnas de %CPU y %MEM)
                #   x = procesos SIN terminal asociada
top             # monitoreo dinámico en tiempo real

⚠️ Examen / seguridad: ante sospecha de malware, la primera herramienta es ps aux mirando el modificador x: un proceso sin terminal asociada (sin tty) es síntoma inmediato de virus o ataque, porque suelen correr en background.

Terminal — ver y editar archivos 
nano archivo            # editor de texto plano; guardar/salir con  Ctrl + X
cat archivo             # muestra el contenido
cat -n archivo          # lo muestra con las líneas numeradas
cat a b                 # concatena a y b en la salida
cat a b > salida        # une a y b en un archivo nuevo (el ORDEN de a y b importa)
Terminal — listar y crear directorios 
ls -l           # vista larga: permisos, propietario, grupo, tamaño, fecha
ls -a           # incluye archivos ocultos (empiezan con  .  )
ls -s           # tamaño de los archivos en KB
ls -las         # combina las tres (= ls -l -a -s)

mkdir nombre            # permisos por defecto: dueño rwx ; grupo y otros r-x
mkdir -m 700 nombre     # crea con un modo de permisos específico
mkdir -p a/b/c          # crea todo el árbol de subcarpetas en una sola línea
examen⚠️ Énfasis para examen — permisos y seguridad
  • El permiso 777 nunca se usa por defecto.
  • La columna de permisos de ls -l es clave, sobre todo en directorios.
  • En una carpeta, el permiso de ejecución x permite que otros usuarios entren a ella. A un atacante que implanta un virus le basta con el permiso de ejecución para infectar/corromper el sistema → dejar carpetas o archivos de origen dudoso con x abierto a terceros es el error más peligroso de la administración.
  • ps aux (modificador x): procesos sin terminal asociada = primer punto de revisión ante malware.
