  • El permiso 777 nunca se usa por defecto.

Repaso de arquitectura

El procesador ejecuta el algoritmo y los datos, que están juntos en la memoria principal — "un adminículo electrónico que ejecuta máquinas de Turing".

Von Neumann — compatible con la máquina de Turing. Componentes: controlador (señales de activación), registro de estado, registro de propósito general, contador de programa (PC), ALU y una sola unidad de almacenamiento (programa + datos + pila).

Cuello de botella de Von Neumann: "de un pasito a la vez" — el procesador va a memoria, hace fetch de la instrucción, la decodifica, vuelve por los datos, los procesa en la ALU y escribe. Mientras una fase ocurre, las demás unidades y buses están inactivos.

Modelo Load-Store (Peterson): cualquier programa se puede reescribir con más instrucciones cortas basadas solo en carga y almacenamiento y una ALU simple.

Harvard RISC: separa físicamente instrucciones (solo lectura) y datos (lectura/escritura) → se puede leer y escribir a la vez.

Segmentación (pipelining): 4 etapas concurrentes por ciclo — Fetch → Decode → Execute → Write Back; tras el arranque sale una instrucción por ciclo.

       T1    T2    T3    T4    T5    T6    T7
I1     F     D     E     WB
I2           F     D     E     WB
I3                 F     D     E     WB
I4                       F     D     E     WB
                         └── desde aquí: 1 resultado por ciclo

/proc—Información de procesos del kernel.

Terminal — localización y ayuda

whereis ls      # ruta completa del paquete + sus directorios de config
                #   (útil para migraciones)   ej. -> /usr/bin/ls
which ls        # SOLO la ruta del archivo ejecutable
pwd             # directorio actual (print working directory)
man ls          # manual local del comando (funciona sin internet); salir con  q

⚠️ Examen: distinguir whereis (mapea toda la instalación, documentación y binarios) de which (solo el binario ejecutable).

Terminal — procesos

ps              # procesos de esta terminal: PID, terminal, TIME, comando
kill <PID>       # termina un proceso
ps aux          # TODOS los procesos del sistema (incluidos los del kernel)
                #   a = de todos los usuarios
                #   u = uso de recursos (%CPU, %MEM)
                #   x = procesos SIN terminal asociada
top             # monitoreo dinámico en tiempo real

⚠️ Examen / seguridad: ante sospecha de malware, la primera herramienta es ps aux mirando el modificador x: un proceso sin tty es síntoma inmediato de virus (suelen correr en background).

Terminal — ver, editar y crear

nano archivo            # editor de texto plano; guardar/salir con  Ctrl + X
cat archivo             # muestra el contenido
cat -n archivo          # con líneas numeradas
cat a b                 # concatena a y b en la salida
cat a b > salida        # une a y b en un archivo nuevo (el ORDEN importa)

ls -l           # vista larga: permisos, propietario, grupo, tamaño, fecha
ls -a           # incluye ocultos (empiezan con  .  )
ls -s           # tamaño en KB
ls -las         # las tres juntas (= ls -l -a -s)

mkdir nombre            # por defecto: dueño rwx ; grupo y otros r-x
mkdir -m 700 nombre     # crea con un modo de permisos específico
mkdir -p a/b/c          # crea todo el árbol de subcarpetas en una línea
