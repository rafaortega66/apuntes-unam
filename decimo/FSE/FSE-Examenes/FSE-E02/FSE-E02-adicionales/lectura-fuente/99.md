# Glosario
~ Términos de la Unidad 3 en orden alfabético. El número entre paréntesis es la presentación donde aparece (09 a 18).

| Término | Definición |
|---|---|
| **ACPI** (15, 17) | *Advanced Configuration and Power Interface*: estándar (HP, Intel, Microsoft, Phoenix, Toshiba) que le da al SO el control exclusivo del arranque, la configuración de dispositivos y la energía. Reemplaza a APM y al BIOS de energía |
| **Adquisición / liberación** (15) | Funciones del controlador para tomar (*lock*) y soltar (*unlock*) el acceso exclusivo a un dispositivo |
| **AML** (17) | *ACPI Machine Language*: el lenguaje compacto, tipo pseudocódigo, en que están escritas las tablas ACPI |
| **Aperiódica, tarea** (12) | Tarea de tiempo real que ocurre de forma espontánea y **tiene deadline**; se considera para la planificabilidad (ej. bolsas de aire) |
| **Backport** (18) | Traer un driver más nuevo a un kernel más viejo y estable |
| **Best Fit** (13) | Algoritmo de asignación: recorre toda la memoria y toma el hueco más pequeño que alcance. Lento; deja residuos minúsculos |
| **Bitácora (journaling)** (16) | Registro de las actualizaciones (deltas) del sistema de archivos; con transacciones atómicas permite recuperar el último estado consistente (ext3, ext4, NTFS, JFFS2, YAFFS2, TFAT) |
| **BSOD** (09) | Pantalla azul de Windows: un driver de terceros que falla en nivel kernel sobre la HAL tira todo el sistema |
| **BusyBox** (18) | Un solo ejecutable pequeño con versiones reducidas de muchas utilidades de UNIX; entorno básico para embebidos |
| **Buildroot / Yocto / OpenEmbedded / Linaro** (18) | Herramientas para generar distribuciones de Linux embebido |
| **CFS** (11) | *Completely Fair Scheduler*: el scheduler de Linux desde el 2.6.23; árbol rojo-negro con tiempo virtual |
| **Consumo constante (estático)** (17) | Energía mínima que consume un dispositivo encendido, sin importar su actividad. En la Fit-PC2, ~75 % del total |
| **Consumo dinámico** (17) | Energía que depende de la actividad y de qué componentes están funcionando |
| **Contador de referencias** (13) | Base de la recolección de basura: +1 al asignar un objeto, −1 al salir de su ámbito; en 0 es basura |
| **Contexto** (09, 10) | Registros, contador de programa y pila de un proceso; se guarda y restaura en cada cambio de contexto |
| **Controlador (device driver)** (15) | Software que sirve de interfaz y gestiona el hardware; liga el hardware con el SO, el middleware y las aplicaciones |
| **Controlador dedicado** (15) | 🎯 Ligado a componentes del procesador: caché, MMU, coprocesador aritmético, FPGA integrado |
| **Controlador genérico** (15) | 🎯 Para el hardware de la tarjeta madre: buses (SMBus, I²C, PCI, PCMCIA), memoria externa, teclado, mouse, Ethernet, puertos |
| **CRAMFS** (16) | *Compressed ROM/RAM FS*: solo lectura, sin bitácora, comprimido con zlib, límite de 256 MB; raíz de un embebido |
| **Cuanto / rebanada (time slice)** (10, 11) | Tiempo fijo que recibe una tarea en Round Robin (4 ms en Linux de escritorio) |
| **C-states** (17) | Estados del procesador en G0: C0 ejecuta; C1 en adelante duerme (más profundo = menos consumo y más latencia) |
| **D-states** (17) | Estados de un dispositivo: D0 encendido, D1 y D2 suspendido, D3 hot y D3 cold apagado |
| **Deadline** (10, 12) | Plazo límite de una tarea de tiempo real |
| **Desarrollo cruzado (cross-development)** (18) | Desarrollar en una plataforma (*host*) para otra distinta (*target*), con un tool chain cruzado |
| **EDF** (12) | *Earliest Deadline First*: se ejecuta primero la tarea con el deadline más cercano |
| **Enlace duro (hard link)** (16) | El mismo archivo en varias rutas con distintos nombres; si se modifica uno, cambian todos |
| **Esporádica, tarea** (12) | Tarea que ocurre de forma espontánea, **sin deadline**, y no se considera para la planificabilidad (algunos autores invierten aperiódica y esporádica) |
| **ext2** (16) | Sistema de archivos de Linux sin bitácora, ligero; en embebidos se usa en RAM disks y flash |
| **FAT** (16) | *File Allocation Table*: sectores agrupados en clústeres con identificador único; FAT32 limita los archivos a 4 GB |
| **First Fit** (13) | Algoritmo de asignación: el primer hueco que alcance, buscando desde el inicio |
| **Flush** (16) | Vaciar al medio físico el búfer de escrituras pendientes (al expulsar un dispositivo) |
| **Fragmentación** (13) | La memoria libre queda en huecos no contiguos: aunque la suma alcance, ningún hueco basta |
| **G-states** (17) | Estados globales del sistema: G0 trabajando, G1 dormido, G2 (S5) apagado suave, G3 apagado mecánico |
| **GPOS** (10) | Sistema operativo de propósito general (Linux, Windows, macOS): procesos e hilos, equidad |
| **HAL** (09) | *Hardware Abstraction Layer* de Windows: traduce entre el hardware heterogéneo y el microkernel |
| **Hilo (thread)** (10) | Subproceso dentro de un proceso; comparte su memoria y hereda su prioridad («proceso ligero»). Es la unidad mínima de un GPOS |
| **Inanición (starvation)** (11) | Una tarea de baja prioridad nunca recibe CPU porque siempre hay otra de mayor prioridad lista |
| **INITRAMFS** (16) | 🎯 *Initial RAM FS*: CPIO comprimido con gzip, solo lectura; contiene la raíz inicial de Linux y lo carga GRUB al arrancar |
| **Instanciación** (10) | Crear la estructura del proceso (PID, banderas) y cargar en RAM lo necesario para ejecutarlo |
| **Jiffy** (14) | Unidad de tiempo del scheduler de Linux (4 ms por defecto) |
| **JFFS2** (16) | *Journaling Flash FS*: con bitácora, para flash (NAND), límite de 128 MB, enlaces duros y compresión opcional |
| **Laxitud (laxity)** (12) | Tiempo que falta para el deadline − tiempo de ejecución que todavía falta |
| **Linker** (09, 10) | Enlazador: resuelve las llamadas enmascaradas contra los `.o` y las bibliotecas; en un RTOS genera el binario con direcciones fijas |
| **Llamada a servicio (system call)** (09) | 🎯 La forma en que una aplicación le pide algo al kernel; pasa por 6 pasos: enmascarar, ID, pila, trampa, desenmascarar, ejecutar |
| **Loader** (10) | Cargador: copia el programa a la RAM y lo relocaliza |
| **Mark & Compact** (13) | Recolector que marca los objetos vivos y los mueve juntos al inicio; bloquea el sistema mientras mueve |
| **Mark and Sweep** (13) | Recolector que marca los objetos en uso y borra los no marcados; según la lámina, no bloqueante; deja fragmentación |
| **MAS** (13) | *Memory Allocation System*: carga y descarga procesos, reserva y libera memoria, lleva el registro y mapea la memoria |
| **Memoria compartida** (13) | Comunicación entre procesos por una región común: la más rápida, sin serialización, pero necesita sincronización |
| **Memoria virtual** (13) | Usa páginas y la memoria secundaria para cargar más de lo que cabe en la RAM; se desaconseja en embebidos |
| **MLF** (12) | 🎯 *Minimal Laxity First*: algoritmo dinámico que ejecuta la tarea con menor laxitud |
| **MMU / MAU** (13) | Unidad que traduce el espacio de direcciones de cada proceso a la memoria física por tablas de páginas |
| **Multitarea** (09) | Ilusión de ejecutar muchos programas a la vez, intercalándolos en rebanadas de tiempo |
| **Next Fit** (13) | Algoritmo de asignación: el primer hueco que alcance a partir de donde terminó la búsqueda anterior |
| **NFS** (16) | *Network File System*: monta un dispositivo remoto como si fuera local, basado en RPC y XDR |
| **NTP** (14) | Protocolo para sincronizar la hora por red |
| **Paso de mensajes** (13) | Comunicación entre procesos serializando datos (JSON, XML) por un canal: más caro, con capa de seguridad |
| **Periódica, tarea** (12) | Tarea de tiempo real con periodo conocido y deadline; base de la planificabilidad |
| **Planificabilidad (schedulability)** (12) | Que todas las tareas cumplan sus deadlines; depende de las tareas, su consumo, su periodo y el algoritmo |
| **Pozos de memoria (memory pools)** (13) | Bloques fijos en potencias de 2 reservados de antemano; deterministas y sin fragmentación |
| **PowerTOP** (17) | Herramienta de código abierto que perfila el consumo: estados C y P, interrupciones, accesos a disco |
| **Preemptive (preventivo)** (11) | El SO puede interrumpir la tarea en ejecución si está lista una de mayor prioridad |
| **Proceso** (10) | 🎯 Estructura de datos del SO que encapsula al programa en ejecución: PC, pila, registros, datos y código |
| **Programa / programa en ejecución** (10) | 🎯 Programa: secuencia pasiva y estática en disco. Programa en ejecución: secuencia activa y dinámica en RAM |
| **P-states** (17) | Estados de desempeño dentro de C0: P0 al máximo; P1 a Pn (hasta 16) más lentos y de menor consumo |
| **Quick Fit** (13) | Algoritmo de asignación con una lista auxiliar de huecos por tamaño y posición: muy rápido, gasta memoria extra |
| **Race to sleep** (17) | Terminar el trabajo «de un jalón» para volver pronto a un estado de bajo consumo |
| **RAM disk / RAMFS / tmpfs** (12, 16) | RAM que el SO presenta como disco; volátil, rápida y sin desgaste |
| **Rate Monotonic (RMS/RMA)** (12) | Algoritmo estático óptimo: a menor periodo, mayor prioridad. Cota n(2^(1/n) − 1) → ln 2 ≈ 0.69 |
| **Real-time executive** (12) | Algoritmo de tiempo real que asigna a cada tarea una rebanada fija que se repite periódicamente |
| **Recolección de basura (GC)** (13) | Liberar automáticamente la memoria de los objetos que ya no se usan; no existe en C/C++ |
| **Regla de oro** (12) | 🎯 Σ (Cᵢ / Tᵢ) ≤ 1: la suma de consumo entre periodo de todas las tareas no puede pasar de 1 |
| **Resource reservation** (12) | La tarea anuncia sus requerimientos al crearse; si no es planificable, no se crea |
| **RootFS** (18) | Sistema de archivos raíz: la jerarquía de directorios (FHS) con todos los programas y librerías |
| **Round Robin** (11) | Cada tarea recibe una rebanada fija en una cola circular; el de los GPOS |
| **RTOS** (10, 12) | Sistema operativo de tiempo real: tareas con prioridad fija y deadline en un proceso raíz |
| **S-states** (17) | Estados de suspensión: S1 (todo el contexto), S2, S3 (suspender a RAM), S4 (hibernar), S5 (sin contexto) |
| **SCHED_NORMAL / BATCH / IDLE** (11) | Políticas no RT de CFS: normal (Round Robin), por lotes (rebanada larga) y de muy baja prioridad |
| **SCHED_FIFO / SCHED_RR** (11) | Políticas de tiempo real de Linux, con prioridades 1 a 99, siempre por encima de las no RT |
| **Scheduler** (11) | Planificador: la parte del SO que decide qué tarea lista usa el procesador |
| **Semáforo binario** (14) | 🎯 Mecanismo de sincronización 0/1; con un hilo trabajador evita que se encimen las ejecuciones de un timer periódico |
| **Shortest Job First** (11) | Elige la tarea lista con el menor tiempo estimado (WCET) |
| **Simple FIFO** (11) | Despacha por orden de llegada y deja correr cada tarea hasta el final («multitarea cooperativa») |
| **Swapping** (13) | Mover páginas de la memoria principal a la secundaria; lento |
| **System tick** (09, 14) | Interrupción periódica del temporizador del sistema que usa el scheduler para cambiar de contexto |
| **Tarea (task)** (10, 12) | Unidad mínima de un RTOS: un tipo de hilo con prioridad preasignada, deadline y scheduler de tiempo real |
| **TFAT** (16) | *Transactional FAT*: la FAT1 se modifica al iniciar la transacción y la FAT0 solo si termina |
| **Tiempo real** (10, 12) | 🎯 Toda salida se calcula antes de que llegue la siguiente entrada. Duro: fallar es catastrófico. Flexible: es tolerable |
| **Tool chain** (18) | Compilador, enlazador, ensamblador (e intérprete) para construir el software |
| **Trampa (trap)** (09) | Instrucción (en Linux x86, `INT 0x80`) que cambia de modo usuario a modo kernel |
| **WCET** (11, 12) | *Worst-Case Execution Time*: tiempo de ejecución en el peor caso |
| **Worst Fit** (13) | Algoritmo de asignación: el hueco más grande disponible; deja espacio para crecer |
| **Write asíncrono** (16) | `write` regresa de inmediato; el controlador junta las escrituras en un búfer y las escribe después |
| **YAFFS2** (16) | Sistema de archivos con bitácora para flash NAND, de arranque rápido, con checkpointing; puede ir sin SO |
| **zram** (13) | Swap comprimida dentro de la propia RAM |
