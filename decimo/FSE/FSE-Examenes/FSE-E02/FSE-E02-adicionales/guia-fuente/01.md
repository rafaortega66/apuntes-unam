# 1. Qué hace un sistema operativo
~ La unidad se llama «Sistemas operativos para plataformas embebidas». Su objetivo es conocer los componentes clave de un sistema operativo para poder escoger el más adecuado al desarrollar un sistema embebido.

## El propósito del sistema operativo

### Acceso multiplexado a los recursos
Un sistema operativo provee **acceso multiplexado a todos los recursos compartidos** de una computadora: el **procesador**, la **memoria** y los **periféricos**. Es «el programa de programas»: reparte a cada programa un turno o un pedazo de cada recurso.

Esa tríada organiza toda la unidad:
| Recurso | Quién lo administra | Tema |
|---|---|---|
| Procesador | El **scheduler** (planificador) | Scheduling |
| Memoria | El **sistema de asignación de memoria (MAS)** | Memoria |
| Periféricos | Los **controladores** (*drivers*) | Drivers |

### Las tareas principales
1. **Proveer interfaces** para interactuar con los servicios que están corriendo (las llamadas al sistema).
2. **Manejar y calendarizar procesos:** crearlos (por instanciación de un proceso nuevo, un hermano o un hijo, o por clonación), destruirlos, sincronizarlos y decidir cuándo corre cada uno.
3. **Manejar la memoria:** asignarla, liberarla, paginarla e intercambiarla entre la memoria física y la virtual.

### Multitarea
La multitarea **crea la ilusión** de que el procesador ejecuta muchos programas al mismo tiempo. Esa ilusión la crea el **kernel intercalando la ejecución de los procesos en rebanadas de tiempo**: interrumpe al que corre, guarda su **contexto** (registros, contador de programa y pila) y carga el del siguiente. Es **concurrencia multiplexada en el tiempo**, no paralelismo, y funciona gracias al ***system tick***, la interrupción periódica de un temporizador (los timers de la Unidad 2).

## Linux contra Windows

### Las dos arquitecturas
- **Linux:** las aplicaciones llaman a la **biblioteca de C (glibc)**, que entra al kernel por la **interfaz de llamadas al sistema (SCI)**. Dentro del kernel están el planificador de procesos, el administrador de memoria y los demás subsistemas; abajo, el hardware.
- **Windows:** subsistemas en modo usuario (Win32, POSIX, OS/2) → **servicios ejecutivos** (manejador de E/S, monitor de referencias de seguridad, IPC, memoria virtual, procesos, Plug and Play, energía, objetos, GDI) → drivers en modo kernel y **microkernel** → **HAL** (*Hardware Abstraction Layer*) → hardware.
- **Android** está construido **sobre un kernel de Linux**: kernel (drivers de pantalla, cámara, Bluetooth, flash, Binder para IPC, USB, Wi-Fi, audio, energía) → bibliotecas y *runtime* (máquina virtual Dalvik) → *framework* de aplicaciones → aplicaciones.

### Saltos de privilegio
| | Linux | Windows |
|---|---|---|
| Para ejecutar algo del kernel | **1 salto** (usuario → kernel) | **2 saltos** (usuario → ejecutivo → kernel) |
| Eficiencia | Mayor | Menor: cada salto cambia registros y modo del procesador |

### La HAL
La **HAL** es una capa que traduce entre el hardware heterogéneo y propietario de cada fabricante y el microkernel. El profesor la llamó «una muleta para los tiempos antediluvianos».

### La pantalla azul
Los **drivers de terceros corren en nivel kernel sobre la HAL**. Si uno mal programado le manda una instrucción inconsistente, el sistema no puede aislar el error y **se cae todo** (BSOD, «Your PC ran into a problem…»). Por eso **Linux domina en embebidos y en la industria**.
