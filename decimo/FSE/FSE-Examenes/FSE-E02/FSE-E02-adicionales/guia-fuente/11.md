## Lo básico

### Por qué consume un circuito
Al diseñar un dispositivo hay que **balancear** costo, desempeño, **consumo energético** y tamaño. Casi todo usa **CMOS**, que por dentro son **MOSFETs** que funcionan **cargando y descargando capacitancias**; por eso el consumo se puede estimar:
**P = P_activa + P_energización + P_fuga**
- **P_activa:** la que se disipa **ejecutando las tareas de cómputo**.
- **P_energización:** la que se gasta en **mantener el circuito funcionando**; difícilmente se elimina.
- **P_fuga:** por **fuga térmica**; despreciable a baja frecuencia, **un problema serio a alta frecuencia**.

### La potencia activa: P = C·V²·f
**C** es la carga capacitiva del circuito, **V** el voltaje y **f** la frecuencia. **C no se puede cambiar, pero V y f sí**, y como **V va al cuadrado**, bajar el voltaje es lo que más ahorra.

!!! Ejercicio resuelto (candidato a examen)
- **P0** (máximo desempeño): 2.6 GHz, 1.4 V → P = C · 1.4² · 2.6 = **5.096·C**
- **P5** (ocioso): 1.0 GHz, 1.1 V → P = C · 1.1² · 1.0 = **1.210·C**
- P5 / P0 = 1.210 / 5.096 = **0.24** → **P5 ahorra el 76 %**. La C se cancela: solo necesitas V y f.

### Tres reglas
1. Los **periféricos que no se usan, a bajo consumo**.
2. Si hay pocas tareas, **bajar la frecuencia** del procesador.
3. Si no hay nada que calcular, **autosuspenderse**.
La tecnología que configura voltaje y frecuencia para máximo desempeño o máxima batería se introdujo en el **Pentium M**. Y como el ojo **no percibe cambios arriba de 60 Hz**, esa es la frecuencia ideal para apagar o suspender componentes sin que el usuario lo note.

## Perfiles y tipos de consumo

### Tres perfiles de energía
| Perfil | Cómo es | Ejemplos |
|---|---|---|
| **Constante** | Alimentación ininterrumpida; **máxima eficiencia** | Monitores, controladores, equipo de red |
| **Bajo demanda** | Procesa **en ráfagas** según el usuario; duerme componentes por milisegundos | Celulares, laptops |
| **Esporádico** | **Años con batería**; procesa solo cuando hace falta; carga programable | **Marcapasos**, monitoreo, GPS |

### Constante contra dinámico
- **Consumo constante (estático):** el mínimo que gasta un dispositivo **solo por estar encendido**, sin importar lo que haga. **A menudo domina el total** y solo baja **apagando o durmiendo** el sistema.
- **Consumo dinámico:** depende de **la actividad** y de qué componentes funcionan; si casi todos tienen bajo consumo se reduce mucho. El sistema lo controla **por observación** o **a petición de las aplicaciones**.
- **Caso Fit-PC2 (Atom Z530):** en la práctica, **el 75 % de la energía es consumo estático** (el fabricante dice 66 %). El procesador y su chipset gastan solo **5 W**; los otros **6 W** son del resto de componentes.

### El modelo simple de eficiencia
Consumo = estático + (1 − estático) × uso; eficiencia = uso / consumo.
| Consumo estático | Al 10 % de uso consume | Eficiencia |
|---|---|---|
| **50 %** | 55 % | **18 %** (80 % de eficiencia hasta el 70 % de uso) |
| **10 %** | 19 % | **52 %** (80 % desde el 30 % de uso; 90 % desde el 50 %) |
**A menor consumo estático, más eficiencia**, pero para tener 10 % de estático **cada componente** (no solo el procesador) tiene que cumplirlo.

## ACPI

### Qué es
**ACPI** (*Advanced Configuration and Power Interface*) es una **interfaz estándar** para la alimentación y la configuración de la computadora, hecha por **HP, Intel, Microsoft, Phoenix y Toshiba**. **Reemplaza** al Plug-and-play BIOS, al BIOS de energía y al **APM**; antes, la energía dependía de cada dispositivo. Con ACPI **el SO toma el control exclusivo** del **arranque**, la **configuración de dispositivos**, la **energía** y las **señales externas** (temperatura, botones de encendido y reset).
| Componente | Qué es |
|---|---|
| **Registros ACPI** | Direcciones de memoria fijas para **monitorear y controlar el consumo** de cada componente |
| **BIOS ACPI** | Controla el **arranque** y las transiciones **sleep/active**; **llena las tablas** |
| **Tablas ACPI** | Describen las interfaces del hardware y el estado del sistema, en **AML** (*ACPI Machine Language*) |
- **Sleep:** para **suspender laptops sin reiniciar**; los componentes quedan casi apagados.
- **Idle:** para **ahorrar durante la actividad**; los componentes bajan su consumo por unos segundos.

### Los estados
!!! Para no confundirlos
**G** = todo el sistema · **S** = qué tan profundo duerme · **D** = cada dispositivo · **C** = el procesador mientras el sistema trabaja · **P** = el desempeño del procesador cuando sí está ejecutando (en C0).

| Global (G) | Qué es |
|---|---|
| **G0 Working** | Operación normal; el SO controla el consumo del procesador y los dispositivos |
| **G1 Sleeping** | Parece apagado; las aplicaciones no corren; **despierta con una interrupción** (teclado, mouse, red, botón, timer) en unos segundos |
| **G2 (S5) Soft Off** | Consumo casi cero; **no guarda contexto**: el SO se vuelve a cargar |
| **G3 Mechanical Off** | Apagado de verdad, como desconectarlo; existe por normas de seguridad |

| Suspensión (S) | Qué es |
|---|---|
| **S1** | La menor latencia; **conserva todo el contexto** (RAM, caché, chipset) |
| **S2** | Como S1, pero **pierde la caché y el contexto del procesador** |
| **S3** | Casi todos los periféricos suspendidos; **la DRAM se conserva** (lo que el sistema llama «suspender») |
| **S4** | **Hibernación**: todo el contexto a **memoria no volátil**; consumo mínimo |
| **S5** | Sin contexto; arranca de nuevo desde una imagen |

| Dispositivo (D) | Qué es |
|---|---|
| **D0** | Encendido al 100 %; el mayor consumo |
| **D1** | Suspensión normal; puede despertarse solo |
| **D2** | Suspensión profunda; puede despertarse solo, **sin contexto** |
| **D3 Hot** | Puede arrancar desde apagado sin reiniciarse; contexto mínimo |
| **D3 Cold** | Apagado total; hay que reinicializarlo |
ACPI agrupa los dispositivos en **clases**: audio, puerto COM, pantalla, entrada (teclado, mouse, gamepads), módem, red, PC Card y almacenamiento.

| Procesador (C) | Qué es |
|---|---|
| **C0** | Ejecutando |
| **C1** | Dormido con transición despreciable (instrucción HLT o MWAIT); **obligatorio** junto con C0 |
| **C2** | Menos consumo y más latencia que C1 |
| **C3** | Aún menos consumo y más latencia; puede vaciar la caché; el SO decide si vale la pena |
| **C4…Cn** | Los define el fabricante (desde ACPI 2.0) |
**Estados P**, dentro de C0: **P0** = máximo desempeño y consumo; **P1 a Pn** (hasta 16) = menos frecuencia y voltaje. En multiprocesador, todos deben soportar los mismos estados.

## Software que ahorra energía

### Race to sleep
Los sistemas cambian de alto a bajo desempeño **según la carga**, así que el software debe **terminar todo «de un jalón»**, **evitar transiciones innecesarias** y **quedarse mucho tiempo en cada estado**. (El software tradicional busca modularidad y respuesta rápida, con mucha conmutación; el embebido debe pensar en energía desde el diseño.) Es el mismo principio del marcapasos: despierta, procesa en un instante y se vuelve a dormir.

### PowerTOP
Herramienta de **código abierto** que perfila el consumo: tiempo en reposo y en uso del procesador, accesos a disco, memoria e **interrupciones** por dispositivo. En una Fit-PC2 ociosa mostró el procesador casi siempre en **C6** y en **P3 (800 MHz)**, con los **daemons de red y del mouse USB** usando la mayor parte del CPU. Se usa **con un wattímetro**, por ejemplo para comparar el video de YouTube en Firefox, Chrome o VLC.
**Las 4 fases para evaluar un código:**
0. Identificar el código a evaluar (**CUT**, *code-under-test*).
1. Encontrar su **frecuencia máxima de ejecución** (cuántas veces por segundo corre sin carga), con varias rondas y datos distintos.
2. Medir su **eficiencia a la frecuencia máxima** durante un periodo largo.
3. **Bajar la frecuencia** y ver cómo cambia el consumo (tiempo total de sleep y sleep por intervalo).
