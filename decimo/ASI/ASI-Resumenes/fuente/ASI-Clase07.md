## 1. Modelado con UML y documentación
- **UML = Lenguaje Unificado de Modelado** (Unified Modeling Language).
- Para la materia, los diagramas centrales son el **de componentes** y el **de despliegue**.
- Documentar no es un trámite: sirve para que el equipo entienda el software y para **estandarizar la comunicación**, sobre todo cuando cambian los colaboradores o entra personal nuevo.
Error común: creer que UML es pérdida de tiempo; sin diagramas claros la comunicación del proyecto colapsa.

## 2. Diagramas y código deben coincidir
!!! Criterio de evaluación (examen)
Toda la programación e infraestructura del proyecto debe **coincidir exactamente** con los diagramas UML entregados (componentes, despliegue, estructuras). Si al auditar hay discrepancia con el código o la configuración del servidor, **el proyecto está mal**.
Error común: entregar los diagramas como algo decorativo, sin revisar que reflejen el sistema real.
